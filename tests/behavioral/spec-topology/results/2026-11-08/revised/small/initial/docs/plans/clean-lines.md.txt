# clean-lines 开发工作计划

- **目标：** 交付可由本地编辑器调用、满足 [clean-lines 规范](../specs/clean-lines.md) 的命令行工具，并完成该规范的验收。
- **当前状态：** 本轮仅建立文档；尚未选定语言与依赖，尚无代码或验收执行结果。`tmp/requirements.md` 是已吸收契约的传入材料，不承担后续维护；契约变更维护在规范中。

## 后续工作

| 工作 | 完成条件 |
|---|---|
| 建立实现环境和调用入口 | 选择适合本地编辑器调用的语言与依赖管理方式，明确 `clean-lines` 的本地运行方式；不改变规范规定的命令和数据语义。 |
| 实现整体转换 | 完成 stdin 解码、分行、过滤、去重、排序、reverse 和输出。C01–C08 均有对应实现；非法输入和未知参数不会产生部分 stdout。内部步骤不需要各自建立规范或计划。 |
| 建立验收检查 | 将规范的全部验收案例变为可重复检查，精确核对 stdout 字节、退出码及错误时 stderr；非 ASCII 案例须能区分 code point 排序与 UTF-16 单元排序。 |
| 完成整体验收与交付 | 在选定环境验证实际命令入口及标准流调用，全部验收通过，记录实际结果的可用位置，并提供简明调用说明。失败或未执行的检查保持为未决工作。 |

下一开发会话从选择环境和实现入口开始；跨会话续接时在本计划更新实际完成项、仍失败或未执行的验收、以及下一项行动，不将这些执行状态写入规范。语言和依赖的常规选择无需单独决策记录；任何改变已接受行为的取舍须先与所有者确认。

当前没有已知阻塞。目标交付、验收完成且规范同步后删除本计划；若仍有失败或缺失的验收则继续保留。当前没有责任转移，不另建交接文档。
