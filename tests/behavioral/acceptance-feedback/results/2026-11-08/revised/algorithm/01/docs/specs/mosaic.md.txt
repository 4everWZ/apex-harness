# Mosaic 系统规格

本规格承接项目所有者已接受的 I01–I08、Q01–Q02、A01–A06。内部特征、距离与结果规则由[检索规格](retrieval.md)承接 F01–F08、Q03–Q10。两者共同构成一个工具的当前契约，整体发布、整体验收。

当前结论：尚未实现；没有输入、算法、持久性或性能的实现与验收证据。本轮只建立文档，未运行算法。

## 范围

Mosaic 是只在本地主机运行的重复图片检索工具。调用者传入已解码的像素矩阵；图片格式解码、网络服务和 GUI 不在范围内。特征、索引与检索仅供工具内部使用，没有外部 SDK、模块版本兼容发布或分开的团队。

语言、依赖、内部索引结构和快照格式尚未选择。后续实现可以选择这些方案，但须满足本规格及检索规格，不得把候选方案视为已接受约束。

## 输入与索引状态

| 要求 | 接受的行为 |
|---|---|
| I01 | 图片为非空 H×W×3 的整数 RGB 矩阵，通道范围为 0–255。非法维度、非整数或越界值返回 `INVALID_IMAGE`，索引状态不变。 |
| I02 | H 或 W 小于 8 返回 `IMAGE_TOO_SMALL`。不得通过复制像素或插值悄悄放大输入。 |
| I03 | 每张图片有区分大小写的 UTF-8 `image_id`。同 id 重复添加且像素完全相同，返回原确认，不重建特征；同 id 的像素不同，返回 `ID_CONFLICT`，状态不变。 |
| I04 | 特征与确认只从成功接受的原像素派生；不得自动旋转、裁剪或做 EXIF 修正。矩阵行列顺序由调用者给出。 |
| I05 | 添加、删除、查询按调用顺序串行执行；初版不承诺并发写。 |
| I06 | 单图添加失败不留下部分特征或 id；批添加按数组顺序逐项执行，单项失败不回滚其他成功项。 |
| I07 | 删除不存在的 id 为幂等成功。删除存在的 id 后，不得再返回其旧特征；随后可重新添加该 id，并按新的图片处理。 |
| I08 | 不得修改调用者的像素矩阵；输入返回后，调用者对矩阵的后续修改不得改变已接受的索引内容。 |

## 查询入口与保存恢复

- **Q01**：原始图片不持久化到索引。索引保存 `image_id`、特征，以及用于 I03 的输入内容身份。内容身份的表示方式未选，不能降低“像素完全相同”的判定。
- **Q02**：查询接受已解码图片或索引内 `image_id`。图片使用同一输入与特征规则；id 不存在返回 `NOT_FOUND`。查询不向索引添加内容。
- **A01**：保存包含全部 id 及有效特征、内容身份。恢复后，添加重放、冲突、删除、查询必须与不中断执行一致，不能只恢复查询结果。特征保存恢复精度见检索规格 F06。

## 组合验收

**A02**：除输入、特征和查询距离的独立向量外，必须组合验收以下场景：

| 场景 | 必须建立的结果 |
|---|---|
| 同像素不同 id | 不视为同一 id；id 查询只排除自身，图片查询不隐式排除。 |
| 添加后修改调用者矩阵 | 已接受的特征与内容身份不受影响；原像素重放仍按 I03 处理。 |
| 删除重加 | 旧特征不再出现；同 id 重加按新图片接受。 |
| 同距离平局 | 使用 Unicode code point 顺序决胜。 |
| 阈值恰好等于距离 | 候选被包含。 |
| k 超出现有数量 | 返回全部符合条件的候选。 |
| 恢复后重放 | 与不中断执行的原确认、冲突、删除与查询行为一致。 |

还须覆盖输入表中的错误及状态不变要求、串行操作、批添加部分失败、幂等删除和矩阵不被修改。算法向量与精确结果要求见[检索规格](retrieval.md)。

## 性能验收

- **A03**：固定主机 H1，10000 张已建索引图片，单线程，`k=10`，查询 p95≤50ms。计时包含查询特征计算和距离排序，不包含加载图片与保存索引。
- **A04**：p95 使用 nearest rank。将 N 个样本升序排列，取第 `ceil(0.95*N)` 个，位置从 1 起算；无样本报告 `unavailable`，不得报告 0。
- **A05**：未测量不等于达标。不同主机、图片集、解码条件或近似检索配置的结果不能当作同条件提升。逐次参数及原始实验结果由已有运行输出持有，不堆入规格。
- **A06**：当前没有可引用的实现或性能证据；未选的语言、依赖、索引结构、快照格式不构成已接受约束。

H1 的实际配置、性能图片集及采样安排尚未给出，见[当前开发计划](../plans/mosaic.md)。这些空缺不改变 50ms 目标或精确检索要求。
