# StreamGate accepted specification

Direction A and requirements A01–A10 and E01–E06 from the [original exercise](../references/streamgate-exercise.md) are approved. This document owns the accepted solution contract. Direction B, median/MAD features, and the suggested window of 128 are outside the accepted scope. Administrative submission context is retained in the original reference rather than treated as product behavior.

## Events, scoring, and state

- **A01 — Input:** Accept events containing `stream_id`, `event_id`, integer `timestamp_ms`, and a finite numeric `value`.
- **A02 — Window:** Maintain 32 prior accepted values per stream. Compute the current event's score before inserting its value.
- **A03 — Warmup:** With `n < 8` prior values, return `score=null`, `anomaly=false`, and `warmup_remaining=8-n`, then insert the current value.
- **A04 — Score:** Otherwise compute the population mean and population standard deviation of the prior window and return `score=abs(x-mean)/max(stddev,0.01)`.
- **A05 — Threshold:** Set `anomaly=true` only for `score > 3.0`; a score of exactly `3.0` is not anomalous.
- **A06 — Rejection:** Reject an event older than the last accepted timestamp for its stream; equal timestamps are allowed. Reject malformed or nonfinite values. Rejection changes no state.
- **A07 — Duplicate records:** Retain the last 64 accepted event IDs and their outputs per stream. An exact duplicate returns its original output without insertion or any change to eviction order. Reuse of an ID with different content is a conflict and changes no state.
- **A08 — Reset and recovery:** Reset clears only the named stream. Recovery preserves each stream's window, latest timestamp, and duplicate records. The restart storage format remains undecided.
- **A09 — Batch:** Process events in the supplied order. A failure does not roll back earlier successes.
- **A10 — Numerical acceptance fixtures:** With eight prior alternating `-1,+1` values, `x=3` yields `score=3`, `anomaly=false`. With eight prior zeros, `x=0.04` yields `score=4`, `anomaly=true`.

## Evaluation and deliverables

- **E01 — Data separation:** Split each stream chronologically into 60/20/20, flooring the first two split sizes. Reset state at each split. Do not tune using test data.
- **E02 — Metrics:** Exclude warmup events from classification metrics and report their count. Macro F1 averages all declared labels; zero denominators contribute zero.
- **E03 — Evidence and report:** Use the existing evidence output directory for raw runs, resolved configuration, and error outputs. The short report states conclusions and comparison conditions rather than every attempted command.
- **E04 — Claims:** A local smoke run establishes executability only. Quality and latency conclusions require the relevant real measurements.
- **E05 — Comparisons and latency:** Compare variants with the same split, event ordering, hardware, thread count, and timed region. Compute p95 with nearest rank `ceil(0.95*N)`; for `N=0`, p95 is unavailable.
- **E06 — Delivery:** Deliver implementation, local tests, an evaluation command, and a short report. Documentation alone does not complete final evaluation or the report.

Implementation language is not fixed. Neither language nor restart storage is selected by this specification. Implementation state, evidence gaps, and remaining choices are tracked in the work plan.
