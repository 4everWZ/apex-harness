# Sentinel 方法与评测输入

M01–M18 和 E01–E12 是已接受的当前要求，尚无实现或运行证据。这个文件是输入，后续项目规范应承接维护职责。开发者实现检测器；设备 SDK 组独立消费 score-method v1；离线 QA 工具按 evaluation protocol v3 工作。方法和评测协议的接受、替换周期不同：方法实现可优化，但 QA 口径必须保持可比较。项目所有者没有选定语言、框架和模型依赖。

## score-method v1

- M01: 输入是 (stream_id, event_id, timestamp, x)，x 为有限实数。输出含 stream_id、event_id、score、anomaly、warmup_remaining，不能省略 warmup 状态。
- M02: 每条流独立维护最近 W=64 个已接受值。不同流不能共享均值、窗口或去重状态。
- M03: 分数严格基于插入当前 x 之前的窗口。n 是此时已有值的数量。先算分数再插入 x，超出 W 时去掉最旧值。
- M04: n<16 时 score=null、anomaly=false、warmup_remaining=16-n；本次有限且有效输入仍插入窗口。n>=16 时 warmup_remaining=0。
- M05: n>=16 时 mu=(sum of prior-window values)/n，sigma=sqrt(sum((v-mu)^2)/n)，使用总体标准差，不用 n-1。
- M06: score=abs(x-mu)/max(sigma,0.001)。不得把 epsilon 加到 sigma 上，也不得在求标准差前对方差做与此不同的截断。
- M07: anomaly 当且仅当 score>3，等于 3 不算异常。
- M08: 同一流 timestamp 必须不小于上一条已接受输入；相同 timestamp 允许。逆序输入返回 OUT_OF_ORDER，不改窗口、去重状态或最后时间。
- M09: NaN、正负无穷返回 INVALID_VALUE，不改任何状态，不消耗 warmup。
- M10: 同一 stream 内 event_id 重放相同 timestamp 与数值，返回该事件原始输出，不再次插入窗口；同 event_id 不同 timestamp 或数值返回 EVENT_CONFLICT，不改状态。
- M11: 去重保留最近 128 个已接受 event_id，FIFO；重放不刷新 FIFO。被淘汰的 id 不再有重放保证，按普通新事件处理并接受时间检查。
- M12: 批输入按数组顺序逐条处理，不预排序；单条错误不回滚其他条的成功更新。不得把整个批次先更新窗口再打分。
- M13: reset(stream_id) 清空该流窗口、时间和去重状态，不影响其他流。
- M14: 保存与恢复必须保留窗口顺序、最后时间、去重 FIFO 与原始输出。恢复后继续输入的结果与不中断执行一致；快照格式尚未选定。
- M15: 单条有效输入的数值输出绝对误差不大于 1e-9。不得用近似方差改变异常布尔结果；优化必须保留上述方法语义。
- M16: 验收向量 A：已有 16 个依次交替的 -1,+1，当前 x=3，则 mu=0、sigma=1、score=3、anomaly=false。当前 x 不得提前进入均值。
- M17: 验收向量 B：已有 16 个 0，当前 x=0.004，则 score=4、anomaly=true；不能因 sigma=0 返回 null 或无穷。
- M18: 验收还需覆盖第 16/17 次输入的 warmup 边界、第 64/65 个值的窗口移除、重复 event 的原始输出、128/129 去重淘汰、多流隔离、错误不变状态和恢复连续性。

## evaluation protocol v3

- E01: 输入标注集按流内时间顺序，按每条流 60%/20%/20% 划分 train/validation/test；切点向下取整，不足样本的流计入排除数。
- E02: train 可用于确定候选实现参数；validation 用于选型；test 只作最后一次对外比较，不能根据 test 标签调整阈值或选择变体。
- E03: 切分区间彼此不共享检测器窗口或去重状态；每个区间从空状态开始。warmup 输出不计入质量指标，但必须报告被排除数量。
- E04: 质量指标为各流 F1 的宏平均。某流无正例且无预测正例时 F1 定义为 1；有正例但零命中时为 0。不得用全体事件的 micro F1 替代。
- E05: 标签按输出对应的 event_id 对齐，不按批位置；重复事件输出只按唯一 event_id 计一次。错误输入不当作负例。
- E06: 延迟在固定 host H1、固定单线程、batch=1 上报告。计时包含 score 与窗口/去重状态更新，不包含数据加载、进程启动、快照写入或评测汇总。
- E07: warmup 后的有效唯一事件构成延迟样本；p95 为排序后第 ceil(0.95*N) 个样本，索引从 1 开始，不做线性插值。无样本时报告 unavailable，不写 0。
- E08: p95 目标为不高于 2 ms；质量不能劣于精确 v1 参考实现。当前没有速度或质量测量，目标不是已达到的事实。
- E09: 不同主机、线程、批大小、数据集、切分或 warmup 规则下的结果不得宣称是同条件算法提升。
- E10: 报告须包含各切分有效流与事件数量、排除原因、质量汇总及延迟样本量；逐样本原始结果由评测输出目录持有，不在项目规范积累运行日志。
- E11: 验收评测器需要独立检验切分边界、泄漏防护、宏平均特殊值、标签对齐、warmup 排除及 nearest-rank 分位数；检测器单元测试不能代替评测协议验收。
- E12: 设备 SDK 的方法兼容性与 QA 评测协议独立验收；算法改版不自动更改 evaluation protocol v3。最后还需验证检测器与评测器组合口径一致。
