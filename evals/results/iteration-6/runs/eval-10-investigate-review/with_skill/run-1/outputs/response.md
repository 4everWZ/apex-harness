# APEX coordination boundaries

Route this scenario to `coordinating-subagents` in two modes: independent investigation first, then independent review. The controller retains ownership of scope, authority, integration, and the final claims throughout.

1. Assign each of two investigators one distinct, independent question, the repository scope it may inspect, and the evidence it must return. Their assignments are read-only: delegation alone grants no mutation authority. Run them concurrently because they share no mutable state and have no sequential dependency. Each returns concise findings, evidence, checks performed, unresolved risks, and deviations.
2. The controller reconciles the reports against repository truth; disagreements are resolved by inspecting the repository, not by voting. The reports are inputs rather than proof or sources of truth. Any implementation informed by the investigations must be separately authorized and owned, with non-overlapping edit boundaries if delegated. The controller then inspects the actual diff and verification evidence.
3. Give a fresh reviewer no implementation ownership and only the context needed to review: intended behavior, relevant source documents, the exact commit/diff range or working-tree scope, available verification evidence, and the risk focus. The reviewer inspects the real repository diff and returns findings ordered by severity with precise paths and rationale. A clean review does not prove that tests ran.
4. The controller verifies each review premise, resolves accepted findings coherently, rejects unsound advice with evidence, and closes missing or stale evidence before claiming completion.

Coordination does not implicitly authorize file edits, commits, pushes, merges, discards, deployment, messaging, or any other external mutation. Git and the approved plan remain the source of truth; do not create a parallel run ledger or review-package protocol. Material product, research, data, evaluation, architecture, or public-contract tradeoffs still require a user decision.
