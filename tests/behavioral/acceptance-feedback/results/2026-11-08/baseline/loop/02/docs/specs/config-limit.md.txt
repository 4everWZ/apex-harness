# 配置值解析规格与验收

本文件维护 LimitDesk 当前已接受的配置解析契约、当前符合性与验收结论，以及尚待处理的客户意见。初始契约来自已接受的 `tmp/srs.md`；该输入不再同步维护。

## 当前接受要求

本地编辑器调用 `parser.parse_limit(value=None)` 读取用户配置。

- 缺省调用或传入 `None` 返回整数 `30`。
- 显式值仅接受 Python `int`，范围为 `5` 至 `120`，包含两端；返回该整数。`bool` 不视为可接受的整数。
- 其他类型和越界值抛出 `ValueError`；不隐式转换字符串或浮点数，异常时不返回部分结果。
- 函数不执行文件或网络 I/O，不修改输入或外部状态；实现无第三方依赖。
- 当前没有性能目标。

## 当前实现与验收

`parser.py` 目前不符合类型拒绝契约：它先调用 `int(value)` 再检查范围，导致字符串 `"30"` 和浮点 `30.0` 返回整数 `30`。默认值和整数边界行为仍符合要求。接受要求不随此次实现变化而改变。

已运行 `python -m unittest discover -s tests`：共 3 个测试，`test_invalid` 的 `"30"`、`30.0` 两个子案例失败（未抛 `ValueError`）；默认值、边界以及其余已有拒绝案例通过。当前原始输出见 [unit.txt](../../evidence/unit.txt)。

| 接受范围 | 已有检查 | 当前结论 |
|---|---|---|
| 缺失值返回 `30` | `test_default` 检查无参调用；实现核对确认显式 `None` 进入同一分支 | 已实现；默认调用测试通过 |
| 接受整数闭区间 | `test_bounds` 检查 `5`、`120`；实现核对区间判断 | 已实现；两端测试通过 |
| 拒绝类型与越界值 | `test_invalid` 检查 `4`、`121`、`True`、`"30"`、`30.0` | `4`、`121`、`True` 通过；`"30"`、`30.0` 失败；类型拒绝未完成 |
| 无 I/O、无状态修改、无第三方依赖；异常无部分结果 | 核对函数实现 | 函数无显式 I/O、赋写外部状态或第三方依赖，抛异常时无返回值；`int(value)` 对任意对象的转换需在类型拒绝修复中移除 |
| 性能 | 没有接受的性能目标；没有性能测量 | 无待完成的性能验收 |

当前功能验收未通过；已明确的修复由[契约修复计划](../plans/config-limit-repair.md)跟进。当前没有性能目标或性能测量；客户体验意见尚不足以建立性能验收标准。本轮没有修改实现。
