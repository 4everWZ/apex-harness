# evaluation protocol v3

本文拥有 Sentinel 离线 QA 评测合同及评测器验收，承接已接受的 E01–E12。其接受和替换独立于 score-method 的版本变更。

## 数据划分与使用边界

- 标注输入按流内时间顺序，每条流按 60%/20%/20% 划分 train、validation、test，切点向下取整；不足样本的流计入排除数（E01）。切点的具体整数算法及不足样本门槛尚未给定，实际切分前须澄清，不能私自补定。
- train 可用于确定候选实现参数，validation 用于选型，test 仅作最后一次对外比较；不得根据 test 标签调整阈值或选择变体（E02）。这不授权候选实现偏离其已接受方法合同。
- train、validation、test 彼此不共享检测器窗口或去重状态，每个区间从空状态开始（E03）。

## 标签、排除与质量指标

标签按输出对应的 event_id 对齐，不按批位置；在多流数据中须保留流归属，避免同名 event_id 跨流混淆。重复事件输出只按唯一 event_id 计一次；错误输入不作为负例。warmup 输出不计入质量指标，必须报告排除数量（E03、E05）。

质量指标为各流 F1 的宏平均，不得替换为所有事件聚合的 micro F1（E04）。对参与汇总的每条流，以符合上述计数条件的事件计算：

```
F1 = 2*TP / (2*TP + FP + FN)
macro_F1 = sum(F1 for each included stream) / number_of_included_streams
```

特殊值：流内无正例且无预测正例时 `F1=1`；有正例但零命中时 `F1=0`。没有正例但有预测正例时，公式给出 `F1=0`。完全没有可计入事件的流及全部流均被排除时如何汇总，尚待明确；不得用任意默认值掩盖缺失。

## 延迟与比较条件

延迟必须在固定 host H1、固定单线程、`batch=1` 下报告。计时包含 score 计算及窗口、去重状态更新；排除数据加载、进程启动、快照写入和评测汇总（E06）。H1 的具体环境尚待确定。

warmup 后的有效唯一事件构成延迟样本。对 N 个样本升序排列后，p95 取第 `ceil(0.95*N)` 个值，序号从 1 开始，不做线性插值。N=0 时报告 `unavailable`，不得写 0（E07）。

p95 目标为 `<=2 ms`，质量不得劣于精确 v1 参考实现（E08）。不同主机、线程数、批大小、数据集、切分或 warmup 规则的结果，不得宣称为同条件算法提升（E09）。目标不是达成声明。

## 评测输出责任

报告须包含各切分的有效流数、有效事件数、排除原因、质量汇总及延迟样本量。报告条件须足以判断是否满足上述比较约束。逐样本原始结果由评测输出目录持有，不在项目规范中积累运行日志（E10）。输出目录和格式尚未选择。

## 评测器独立验收

评测器必须独立检验下列条件，检测器单元测试不能代替这些验收（E11）：

| 范围 | 验收检查 |
| --- | --- |
| 切分边界 | 每流比例、向下取整、不足样本排除符合最终明确的 E01 定义；各区间数量可核对 |
| 泄漏防护 | 各切分从空状态开始，无窗口或去重跨区间残留；train/validation/test 用途符合 E02 |
| 宏平均 | 逐流算 F1 后等权汇总；覆盖无正例且无预测正例取 1、有正例但零命中取 0，避免 micro F1 替代 |
| 标签对齐与唯一计数 | 按 event_id 及所属流关联，覆盖输出顺序变化、重复事件、跨流同名 id；错误不作为负例 |
| warmup 排除 | 质量与延迟样本按各自定义排除 warmup；报告包含相应排除数量 |
| nearest-rank p95 | 覆盖非整数 rank、小样本及 N=0，核对一基序号且不插值 |
| 计时与报告 | 检查 H1、单线程、batch=1、计时边界及必报数量和排除原因；不同条件不标为同条件提升 |

设备 SDK 的方法兼容性与 QA 协议须独立验收，之后还需进行检测器与评测器组合口径验收（E12）。
