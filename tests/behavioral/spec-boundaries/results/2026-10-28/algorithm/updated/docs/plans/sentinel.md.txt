# Sentinel 实现与评测准备

## 目标与当前状态

协调检测器、设备 SDK 方法兼容性和离线 QA 的分会话实现与验收，直到独立契约及组合口径均有符合性证据。

当前维护职责由两个独立契约承接：[score-method v2](../specs/score-method.md) 和 [evaluation protocol v3](../specs/evaluation-protocol.md)。[原始传入材料](../../tmp/method-brief.md) 与 [已接受方法变更](../../tmp/accepted-method-change.md) 均是只读基线输入，不承担后续规范维护。v2 的窗口、warmup 与验收边界已同步至当前方法规范；QA v3 仅将参考方法切换为 v2。本轮仅维护文档；尚无实现、测试或实验结果，不能声称方法符合、评测器正确、性能达标或方法变更带来提升。

## 未决事项

- 输入/API 表达：timestamp 的类型与单位、stream_id/event_id 的表示、错误返回结构，以及多种错误条件同时成立时的优先级尚未给定。保留已接受重放语义，不得让普通过时检查覆盖合法的原事件重放。
- 快照：格式、持久化接口与兼容策略未选定；窗口顺序、最后时间、去重 FIFO、原始输出和恢复连续性已经是必须满足的要求。
- E01 的“不足样本”判定尚未给出。需明确哪些流排除、如何计数；不能以猜测的长度阈值开始正式比较。
- 某切分在排除 warmup、错误及重复后，流无质量样本或整个切分无有效流时，质量汇总如何表达尚未给定；不能自动把无样本流当作 F1=1 的无正例流。输入重复 id 的标签若冲突，处理规则也需明确。
- host H1 的具体配置、数据集身份与版本、评测输出目录和精确 v2 参考实现的可用位置尚未给出。正式比较须固定并记录条件；不同条件不能宣称为同条件提升。
- 语言、框架、依赖和实施责任人尚未指定。补齐选择后再开展对应实现工作。

这些是待澄清项，不是新增的已接受行为。本轮不作实现、实验、部署或依赖安装。当前已接受的方法为均值/总体标准差、W=128、至少 32 个历史值；median/MAD 替代仍未接受，不安排以更换评测定义证明改进。

方法符合性、QA 协议独立验收、检测器与评测器组合一致性以及固定条件下的质量/延迟目标均需各自证据。文档静态核对只能支持本轮契约承接与文档一致性，不能当作行为验收或性能证据。待本目标完成并同步所有已接受契约变更后，按项目文档生命周期清理本工作计划。
