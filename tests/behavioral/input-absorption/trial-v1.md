# Proposed input-consumption clarification

This is trial wording for evaluation, not an applied skill change. Scope is two existing paragraphs; no new section, directory, workflow, validator, or lifecycle.

## Input consumption

Replace managing-project-docs/SKILL.md's existing input-consumption paragraph with:

> Consume inputs without such maintenance responsibilities in place. Incorporate accepted requirements into their specification owner; keep relevant unresolved targets and execution constraints in working context or the current plan. Leave the source unchanged: do not move it into project documentation or create a persistent original-text copy merely for traceability, a stable reference, or preservation.

This applies to inputs without a user- or repository-established maintained role. Explicit user instructions and actual document responsibilities still take precedence. Accepted requirements, unaccepted targets, implementation state, evidence, and optional plans retain their existing roles. Source preservation is not authorization to move or duplicate it.

## Convention recognition

Append to topology.md's existing convention-recognition paragraph:

> An index entry written for a new artifact does not itself establish a convention or retention need.

The added sentence prevents self-justification through a README entry; it does not require asking permission for ordinary path choices or for documents with a genuine contract or working responsibility. Do not change retirement, recovery, document-layer boundaries, APEX, or templates.
