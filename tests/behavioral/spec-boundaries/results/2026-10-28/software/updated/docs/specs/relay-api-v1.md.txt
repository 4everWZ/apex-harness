# Relay 公共任务 API v2

本文件维护当前已接受的公共 API v2 契约，供移动端与合作方 SDK 的实现和验收使用。R01–R12 的编号继续使用，其中 R04 和 R11 已按所有者接受的 v2 要求更新；其余公共 API 行为不变。尚未确定的传输绑定和字段细化不得视为已经选定。

## 租户与创建

- **R01**：调用者只能读取和创建自己 tenant 的任务；跨 tenant 查询与不存在任务统一返回 404，不泄露存在性。
- **R02**：创建必须提供 job_type 与 JSON payload；job_type 必须是该租户允许的已注册类型。未知类型返回 422，且不创建任务。
- **R03**：创建请求必须携带 1–128 个 ASCII 字符的 Idempotency-Key。缺失或格式不合要求返回 400，不产生任务。
- **R04**：幂等范围为 tenant + key。首次创建后 72 小时内，相同 key 与相同规范化请求的重放返回同一 job_id 和原创建响应，不重复创建。不同 tenant 可以独立使用相同 key。
- **R05**：上述范围内，同 key、不同请求返回 409。按解析后的 JSON 结构比较请求，忽略对象键顺序，保留数组顺序；整数 1 与浮点 1.0 视为相同数字。

## 状态与取消

- **R06**：状态为 queued、running、succeeded、failed、cancelled。succeeded、failed、cancelled 为终态，不允许回到非终态。
- **R07**：首次创建为 queued；领取成功才进入 running；成功或不可重试失败分别进入相应终态。
- **R08**：取消 queued 任务立即进入 cancelled。取消 running 任务只登记取消请求，在 worker 确认后才进入 cancelled，不得虚报已停止。
- **R09**：取消请求与成功结果并发时，以服务端先成功提交的终态转换为准，后到结果不能改写终态。重复取消必须幂等。

## 获取与列表

- **R10**：获取任务返回 job_id、job_type、state、created_at、updated_at、cancel_requested；终态失败另有 error_code。禁止返回 worker stack 或 credentials。
- **R11**：列表按 created_at 降序排列，同时间按 job_id 降序打破平局。使用不透明 cursor，page_size 为 1–100；游标无效返回 400。任何页面不得混入其他 tenant 数据。

## 验收

覆盖 R01–R11 的正常、拒绝和边界行为，包括 tenant 隔离、无效创建不产生任务、幂等键长度与 ASCII 限制、72 小时重放窗口、JSON 规范化差异、状态转换、取消确认、输出字段和稳定分页。针对 v2，覆盖首次创建后超过 24 小时但仍在 72 小时窗口内的相同请求重放与不同请求冲突；列表使用多个 created_at 相同且跨页的任务，检查 job_id 降序及 cursor 连续性。

**R12**：幂等与终态行为必须通过并发请求验收。至少覆盖同 tenant 同 key 的相同请求并发、不同请求冲突，以及取消与成功提交竞争；检查任务数量、响应身份和最终状态。单次 happy-path 示例不能作为完整验收。具体测试工具和基础设施不由本契约指定。
