# StreamGate development plan

## Goal and current state

Complete the implementation, local tests, reproducible evaluation command, and evidence-supported short report for the [accepted StreamGate specification](../specs/streamgate.md) across two future development sessions.

Only project documentation is prepared. Implementation, tests, experiments, measurements, and report conclusions are unfinished. The [complete original exercise](../inputs/streamgate-exercise.md) is preserved for the external review from a clean checkout. Do not treat unselected directions or appendix suggestions as approved work.

## Choices and inputs still needed

- Implementation language and tooling remain undecided. Select them in a future authorized development session before implementation.
- Restart storage format remains undecided. Select it before implementing and verifying recovery; preserve all A08 state regardless of format.
- Confirm the callable or command interface, malformed-event and conflict output representation, and exact-content equality rules for duplicate events. The contract requires original-output replay for exact duplicates, including when later accepted timestamps exist; define processing order to preserve that obligation alongside A06.
- Obtain the evaluation dataset, its declared labels, and the existing evidence output directory required by E03. No directory or dataset was present in the supplied project. Do not silently replace the required evidence location or invent quality results.
- Agree on the measured variants, target hardware, thread count, and timed region before comparisons. No quality or latency acceptance threshold was supplied; do not invent one or infer measured quality from a smoke run.

## Session 1: detector and state correctness

1. Resolve the implementation choices and interface details above without changing the accepted requirements. Record any proposed change distinctly and seek acceptance before changing scope or semantics.
2. Implement event validation, per-stream rolling statistics, warmup, and strict anomaly threshold.
3. Implement timestamp handling, duplicate replay and conflict handling, bounded duplicate retention, reset, recovery, and ordered partial-success batches.
4. Add local tests that exercise the requirement groups below. In particular, verify unchanged state on rejection and conflict, unchanged duplicate eviction order on replay, state isolation across streams, and equivalent behavior after recovery.
5. Leave the implementation and local verification state in this plan with the next concrete action for session 2. Do not claim evaluation completion from local tests.

## Session 2: evaluation and final deliverables

1. Resolve missing evaluation inputs and the existing evidence directory before running evaluation.
2. Implement reproducible evaluation with chronological per-stream splits, split resets, warmup exclusion and count, declared-label macro F1, and nearest-rank p95.
3. Provide evaluation commands and resolved configuration sufficient to reproduce the chosen run. Keep raw runs and errors in the existing evidence output directory.
4. Run local checks and smoke execution, then obtain real quality and latency measurements under matched comparison conditions. Keep the conclusions limited to the measurements obtained.
5. Write the short report with conclusions and comparison conditions, and compare the accepted solution and final deliverables against the complete versioned original. Confirm the README links and original source remain available in a clean checkout.
6. Update this plan to reflect remaining gaps. Retire it only after its goal is delivered and verified, or explicitly cancelled or superseded with still-current constraints preserved.
