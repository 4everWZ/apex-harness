# Mosaic 产品与技术规范

## 范围与维护职责

Mosaic 是本地主机上的重复图片检索工具。调用者提供已经解码的像素矩阵；工具负责输入处理、特征计算、索引变更、精确检索及保存与恢复。不包含图片格式解码、网络服务或 GUI。

本文承接所有者已接受的 I01–I08、F01–F08、Q01–Q10、A01–A06，是这些产品目标、算法定义及验收条件的维护位置。已接受的要求可以先于实现存在；本规范不声明实现已完成或验收已通过。后续接受的合同变更应更新本文。实现进度和未决选择由工作计划维护。

特征、索引与检索仅供本工具内部使用，无外部 SDK、模块版本兼容发布或分开的团队。Mosaic 整体发布、整体验收；以下章节共同定义同一工具的合同。

## 输入与状态变更

- **I01**：图片为非空 H×W×3 的整数 RGB 矩阵，通道范围 0–255。非法维度、非整数或越界值返回 `INVALID_IMAGE`，索引状态不变。
- **I02**：H 或 W 小于 8 返回 `IMAGE_TOO_SMALL`；不得通过复制像素或插值悄悄放大输入。
- **I03**：每张图片有区分大小写的 UTF-8 `image_id`。同 id 重复添加且像素完全相同，返回原确认，不重建特征；同 id 不同像素返回 `ID_CONFLICT`，状态不变。
- **I04**：特征与确认只从成功接受的原像素派生；不得自动旋转、裁剪或做 EXIF 修正。矩阵行列顺序由调用者给出。
- **I05**：添加、删除和查询按调用顺序串行执行；没有并发写承诺。
- **I06**：单图添加失败不得留下部分特征或 id。批添加按数组顺序逐项执行，单项失败不回滚其他成功项。
- **I07**：删除不存在的 id 为幂等成功。删除存在的 id 后不得再返回其旧特征；删除后可重新添加该 id，按新图片处理。
- **I08**：不得修改调用者的像素矩阵；输入返回后，调用者对矩阵的后续变更不得改变已经接受的索引内容。

## 特征定义

- **F01**：逐像素计算亮度 `L=(299R+587G+114B)/1000`，不舍入为整数，不做 gamma 修正。
- **F02**：以 8×8 网格覆盖原矩阵。网格行 i 对应半开区间 `[floor(i*H/8), floor((i+1)*H/8))`，列 j 对应 `[floor(j*W/8), floor((j+1)*W/8))`，i、j 均从 0 到 7。不得用均匀取样点替代分区均值。
- **F03**：每个单元 `m[i,j]` 为对应区域全部亮度的算术平均。全局均值 `mbar` 为 64 个单元均值的算术平均，不是原图所有像素的均值。
- **F04**：当且仅当 `m[i,j]>=mbar` 时，`b[i,j]=1`。按行优先将 `(0,0)` 到 `(7,7)` 映射到 bit 0 到 bit 63；不得按字节端序反转位序。
- **F05**：分别计算 RGB 各通道的全图均值并除以 255，得到 `c=(cR,cG,cB)`，三个分量均在 `[0,1]`。
- **F06**：图片特征为 `(64 位 b, c)`。保存与恢复必须保留足以按同样规则比较的值，误差不大于 `1e-12`；不得压缩为会改变排序的低精度格式。
- **F07**：任意常量色图片的 64 位都为 1；不得因等于均值而产生全零。8×8 图像中仅左上像素为白、其余为黑时，仅 bit 0 为 1。
- **F08**：非整除尺寸验收须覆盖 9×17 等矩阵，检查 floor 分区以及 64 单元等权。不得用缩放到 8×8 的库默认行为替代 F02–F03。

## 索引与查询

- **Q01**：原始图片不持久化到索引。索引保存 `image_id`、特征及用于判定 I03 的输入内容身份。身份表示方式尚未选择，不得降低像素完全相同的判定。
- **Q02**：查询可传已解码图片或索引内 `image_id`。图片遵守同一输入和特征规则；id 不存在返回 `NOT_FOUND`。查询不向索引添加内容。
- **Q03**：Hamming 距离 h 为两个 64 位特征异或后的 1 位数；归一化距离 `h'=h/64`。
- **Q04**：颜色距离 `d=(abs(cR-qR)+abs(cG-qG)+abs(cB-qB))/3`；总距离 `D=0.75*h'+0.25*d`。不得改为欧氏距离或先将两个分量舍入。
- **Q05**：仅保留 `D<=max_distance` 的候选，边界相等时包含。`max_distance` 必须为 `[0,1]` 内有限数；非法值返回 `INVALID_THRESHOLD`。
- **Q06**：k 必须为 1–100 的整数；非法值返回 `INVALID_K`。结果不足 k 时全部返回；空索引返回空数组。
- **Q07**：按 D 升序排列；D 相等时按 `image_id` 的 Unicode code point 升序稳定决胜。不得用插入顺序、locale 或显示文件名破平局。
- **Q08**：用索引内 id 查询时，仅排除该 id 自己，其他内容相同的不同 id 仍可返回。图片查询不做隐式自排除。
- **Q09**：每项结果返回 `image_id`、D、原始整数 h 和颜色距离 d。显示值可以另行格式化，排序和门限判断必须使用未舍入数值。
- **Q10**：初版返回结果必须与全量精确扫描相同。内部索引结构可选择，未经接受不得采用近似检索、提早截断或通过丢候选提升性能。

## 持久性与验收合同

- **A01**：保存包含全部 id 与有效特征、内容身份。恢复后添加重放、冲突、删除、查询行为必须与不中断执行一致，不得只恢复查询结果。
- **A02**：除输入、特征和查询距离的独立向量验收外，还须组合验收：同像素不同 id、添加后修改调用者矩阵、删除重加、同距离平局、阈值恰好相等、k 超出现有数量、恢复后重放。
- **A03**：性能目标是在固定主机 H1 上、10000 张已建索引图片、单线程、k=10 的查询 `p95<=50ms`。计时包含查询特征与距离排序，不含加载图片和保存索引。
- **A04**：p95 使用 nearest rank：样本升序后取第 `ceil(0.95*N)` 个，位置从 1 起始；无样本报告 `unavailable`，不得报告 0。
- **A05**：未测量不等于性能达标。不同主机、图片集、解码条件或近似检索配置的结果不得作为同条件提升。逐次参数和原始实验结果由运行输出持有，不堆入本规范。
- **A06**：语言、依赖、索引结构和快照格式未选择；这些未决项不是所有者已接受的产品约束。不得将未作出的选择表述为已接受决定。

## 验收方法

以下是未来实现的验证入口，不是已完成的验证结果。

| 要求 | 验证方法与可观察结果 |
|---|---|
| I01–I02、I04、I08 | 用非法维度、非整数、越界、过小矩阵及有效矩阵检查错误和状态不变；比较调用前后矩阵，并在添加返回后修改调用者矩阵，确认索引不受影响。 |
| I03、I05–I07 | 按调用顺序检查相同 id 相同像素重放、相同 id 不同像素冲突、批处理中间失败、删除不存在 id、删除后查询及重加；检查确认、特征重建与部分状态。 |
| F01–F08 | 以独立计算的亮度、单元均值、全局均值、位序和通道均值作为向量期望；覆盖常量色、左上单白像素及 9×17 非整除输入，并检查保存恢复误差及排序不变。 |
| Q01–Q10 | 检查图片查询与 id 查询、缺失 id、两个距离分量与总距离、非法阈值及 k、边界包含、Unicode code point 平局顺序、自排除、空索引及不足 k；与全量精确扫描的完整有序结果比较，并检查查询未改变索引。 |
| A01–A02 | 对同一操作序列分别执行不中断路径及保存恢复路径，比较重放确认、冲突、删除和查询；组合覆盖 A02 全部场景。检查持久内容没有原始图片。 |
| A03–A05 | 在约定 H1、图片集和计时范围下采集查询耗时，按 nearest rank 计算 p95；检查无样本语义及结果条件的一致性，以运行输出承载参数和原始样本。 |
| A06 | 检查实现选型及相应文档，区分已接受约束与实现选择，确认未以选型或优化改变既有语义。 |
