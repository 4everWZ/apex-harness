## Session 1 — Implementation and local verification

1. Read the specification and this plan. Resolve language and restart storage with the user; record accepted choices in their owning contract sections when they constrain the maintained interface. Keep unresolved choices here.
2. Establish the chosen project environment and define event, output, reset, batch, and recovery interfaces. Resolve material interface ambiguities with the user before implementing affected behavior.
3. Implement per-stream scoring and window handling, validation, duplicate records, reset, recovery, and ordered batches.
4. Add and run local tests covering the mapping below, including the required A10 fixtures. Verify state preservation on rejected events and conflicts, duplicate eviction order, cross-stream isolation, reset isolation, and recovery continuation.
5. Record the actual implementation locations, tests performed, remaining failures, and next action in this plan. A successful local smoke run supports executability only; leave quality and latency claims pending.

Resume boundary: if a choice remains unresolved, leave the dependent task open with its exact blocker. At session end, update the current state rather than adding a session diary. Session 2 starts by closing any remaining Session 1 contract or correctness gaps.

## Session 2 — Evaluation and final deliverables

1. Confirm dataset, labels, evidence destination, variant set, hardware, thread count, and timed region. Resolve missing dependencies before running evaluation.
2. Build a reproducible evaluation command using the approved language and project environment. Implement chronological per-stream splitting, split resets, warmup accounting, macro F1, and nearest-rank p95. Verify small and empty-input metric cases and split rounding.
3. Run the actual evaluation. Save raw runs, resolved configuration, and error outputs to the existing evidence destination. For comparisons, hold E05 conditions equal and avoid test-data tuning.
4. Write the short report from measured results, describing conclusions, comparison conditions, and material limitations. Cite usable evidence locations and include the reproducible evaluation command. Do not substitute smoke success or documentation for evaluation.
5. Check all accepted requirements against implementation and evidence. Update the README with concrete usage and evaluation commands once they exist. Leave unmet requirements and unsupported claims open in this plan.
