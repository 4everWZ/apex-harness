# Relay 开发计划

## 目标与当前状态

从零实现 Relay 已接受契约，使三个消费边界分别完成验收，再完成跨边界一致性验收。工作跨会话持续；本次只准备维护文档，不实现应用、不执行实验、不部署。

规范入口为 [产品契约](../specs/relay.md)，接口所有者为 [公共 API v1](../specs/relay-api-v1.md)、[worker protocol v1](../specs/relay-worker-v1.md) 和 [audit format v1](../specs/relay-audit-v1.md)。这些规范承接已接受要求；本计划只维护未完成工作、待决事项及符合性状态。

当前已有规范与本计划，尚无实现、测试套件、golden 文件或任何实现符合性证据。文档建立不构成接口验收通过。输入 tmp/product-srs.md 保持原样，不承担后续同步职责。

## 恢复执行顺序

1. 在进入相关接口实现前，细化下列阻塞该接口的未决项。涉及可观察行为、数据或验收含义的选择交由项目所有者与相应消费方接受，再更新所属规范；本计划中的问题本身不改变现有要求。
2. 明确持久化、并发提交和审计可恢复方案，并选择需要的框架、数据库、队列或替代方案、部署方式。先检查方案能否满足已接受的不变量，不预设必须采用某个产品或 outbox。
3. 实现公共 API、worker 协议和审计导出，保留各自接口边界；将回归测试和后续长期使用的 conformance suite、golden 文件放在项目约定的受维护位置。任务临时材料留在 tmp/，不能代替测试资产。
4. 分别由 API 消费方、两个外部 worker 提供方、审计消费方完成各自接口验收；修复缺口并维护以下映射。再执行 R31–R33 的跨边界与重启验收。
5. 只有实现和必要验收证据支持交付结论时才结束本计划；若有经接受的契约变化，同步规范后再评价符合性。

当前下一步是收敛接口绑定、审计格式细节及持久化一致性设计。当前文档准备授权不包含执行上述实现或验收。

## 未决事项

以下问题不暂停已经接受的 R01–R36；它们是实现前仍需细化的内容，不能以默认实现悄然补成契约。

- **身份与授权绑定**：如何建立调用者的 tenant 身份，worker 与审计消费者如何认证并限制 tenant 访问。必须保留 404 防存在性泄露和各边界隔离承诺。
- **公共 API 具体接口**：路由、方法、请求与响应封装、标识符与时间字段表示、取消与错误响应细节尚未指定；24 小时幂等窗口结束后的处理也未指定。已明确的错误状态码、字段、规范化规则和并发语义不待重新选择。
- **worker 具体接口**：领取、心跳、结果和取消确认的传输形式、结果数据结构、结果相同的判定、可重试失败分类与错误承载方式，以及 cancel_requested 的送达方式尚需明确。不得改变 lease 边界、次数上限或已命名错误语义。
- **审计具体格式**：kind 枚举字面值、actor_type/actor_id 约束、标识符和 sequence 的数据表示尚未给出；format_version 与 next_sequence 如何承载而不破坏事件字段白名单和 JSON Lines、空批次的 next_sequence 规则仍待明确。创建和开始等事件的对应关系必须保留 R23，不能用格式细化删除应有事件。
- **基础设施与一致性方案**：HTTP 框架、数据库、队列及部署方式未选；任务状态、幂等窗口与审计恢复如何协同持久化未选。方案必须满足提交后审计可恢复及服务重启后的承诺。
- **验收组织与资产**：测试工具、套件位置、各消费方实际执行方式和证据位置尚未建立。验收必须保留并发请求、独立外部 worker conformance suite、审计 golden 文件和跨边界验收四类要求；不存在可以引用的通过结果。

尚无需要独立维护的已选架构决策，故未创建决策记录。后续如有需独立接受或引用的重要选择，再建立其所有者并让受影响规范引用；不以未决方案充当已接受依赖。
