# 配置解析契约修复计划

## 目标与范围

修复现有实现对[已接受配置解析合同](../specs/config-parsing.md)的类型拒绝偏离，并完成受影响范围验收。反馈及证据由[验收记录](../acceptance/config-parsing.md)维护。

本计划只包含已有契约不符合的问题：F1 字符串接受及同类浮点隐式转换。F2 的 `auto` 提议尚未接受，F3 的体验意见尚未明确，均不属于本修复目标，不阻塞本计划完成。

## 当前状态

`parser.py` 在检查前执行 `int(value)`。当前 3 项测试中，`"30"` 与 `30.0` 两个子用例失败；本轮未修改实现和测试。

## 下一会话执行

责任：接续本工作的维护者。

1. 移除隐式转换，恢复精确 Python `int` 类型和含端点的范围检查；保留 `None` 默认值及 `ValueError` 语义。
2. 运行已有测试并将输出覆盖写入 `evidence/unit.txt`；结合实现核对确认类型拒绝、无 I/O 和外部状态修改等合同要求。仅在确有覆盖缺口时补充必要测试。
3. 按实际结果更新验收记录中的 F1、同类缺口及当前结论，同步规格的简要结论。

## 完成条件与生命周期

已有契约缺口修复且受影响范围验证通过后，本计划目标完成。把仍有效的结论与反馈留在持续验收记录，修复当前引用，按仓库恢复保护要求退役本计划；不得因 F2、F3 仍开放而延长本修复计划。
