# Mosaic 内部检索规格

本规格拥有已接受的 F01–F08、Q03–Q10 的技术定义与局部验收。它是系统契约的内部技术层，不建立独立发布或验收流程。输入、索引生命周期、保存恢复及整体结论由 Mosaic 系统规格负责。

## 特征计算

对成功通过输入校验的原始 H×W×3 RGB 矩阵计算特征 `(b,c)`，不做自动旋转、裁剪、EXIF 修正或缩放。

1. **F01**：每个像素亮度为 `L=(299R+587G+114B)/1000`。不舍入到整数，不做 gamma 修正。
2. **F02**：以 8×8 网格覆盖原矩阵。第 i 行区域为 `[floor(i*H/8), floor((i+1)*H/8))`，第 j 列为 `[floor(j*W/8), floor((j+1)*W/8))`，i、j 均为 0–7。分区均值不能被均匀采样点替代。
3. **F03**：`m[i,j]` 是对应区域全部像素亮度的算术平均；`mbar=(Σ_i Σ_j m[i,j])/64`。64 个单元等权，不能将 mbar 改成原图全部像素的均值。
4. **F04**：当且仅当 `m[i,j]>=mbar` 时，`b[i,j]=1`，否则为 0。按行优先将 `(0,0)` 到 `(7,7)` 映射至 bit 0 到 bit 63，即 bit 位置 `8*i+j`。不得按字节端序反转位序。
5. **F05**：RGB 各通道分别取全图均值，再除以 255，得到 `c=(cR,cG,cB)`，分量均在 `[0,1]`。
6. **F06**：特征为 64 位 b 和 c。保存恢复须保留足以按相同规则比较的值，误差不大于 `1e-12`；不得压缩为会改变排序的低精度格式。

## 距离、过滤和返回

对查询特征 `(bq,cq)` 与各候选 `(b,c)`：

- **Q03**：`h=popcount(b XOR bq)`，为原始整数 Hamming 距离；`h'=h/64`。
- **Q04**：`d=(abs(cR-cqR)+abs(cG-cqG)+abs(cB-cqB))/3`，`D=0.75*h'+0.25*d`。不得改成欧氏距离，也不得先舍入两个分量。
- **Q05**：`max_distance` 必须是 `[0,1]` 内的有限数，否则返回 `INVALID_THRESHOLD`。只保留 `D<=max_distance` 的候选，包含相等边界。
- **Q06**：k 必须是 1–100 的整数，否则返回 `INVALID_K`。符合条件的结果不足 k 时全部返回；空索引返回空数组。
- **Q07**：按未舍入的 D 升序排列；D 相等时按区分大小写的 `image_id` 的 Unicode code point 升序稳定决胜。不得使用插入顺序、locale 或显示文件名决胜。
- **Q08**：索引内 id 查询只排除该 id 自己，内容相同但 id 不同的其他图片仍可返回。图片查询不隐式自排除。
- **Q09**：每项返回 `image_id`、D、原始整数 h 和颜色距离 d。显示值可另行格式化，排序和门限判断必须使用未舍入值。
- **Q10**：初版结果须与全量精确扫描完全一致。内部索引结构可以另行选择；未经接受不得采用近似检索、提前截断或丢弃候选来提升性能。

## 算法验收

独立向量必须直接检查上述定义，不以实现内部的一致性代替预期值：

| 要求 | 向量或检查 |
|---|---|
| F01、F05 | 检查原像素亮度及 RGB 全图均值，包括不应被整数舍入的值；颜色分量在 `[0,1]`。 |
| F07 | 任意常量色图片的 64 位全为 1；等于均值不得产生全零。 |
| F07、F04 | 8×8 图片仅左上像素白、其余黑时，仅 bit 0 为 1；检查位序。 |
| F08、F02–F03 | 覆盖 9×17 等非整除尺寸，检查 floor 分区、区域像素全覆盖及 64 单元等权；不得用图片库默认缩放代替。 |
| F06 | 保存恢复特征后检查误差不超过 `1e-12`，且比较、排序语义保持。 |
| Q03–Q04 | 独立检查整数 h、h/64、通道绝对差平均 d 和权重总距离 D，包含能区分欧氏距离及预先舍入错误的向量。 |
| Q05–Q09 | 检查非法门限、非有限值、范围外或非整数 k、门限相等、空索引、结果不足 k、Unicode code point 平局、自排除和返回字段。 |
| Q10 | 在同一输入与状态下，将实际结果与全量精确扫描的结果逐项比较，包含候选、顺序及未舍入距离。 |

组合状态场景和性能目标由系统规格定义，算法局部通过不能替代整体行为与性能验收。
