# Relay Worker Protocol v1 规范

本文件拥有外部 worker 插件协议 v1 的行为和兼容性验收要求（R13–R22）。

## 领取与 lease

- **R13：** 领取返回 `job_id`、`attempt_id`、`lease_token`、`lease_expires_at`、`job_type` 和 `payload`。每次重新领取都改变 `attempt_id`。
- **R14：** Lease 默认 60 秒，worker 每 20 秒心跳。成功心跳从服务端当前时间延长 60 秒；到期时刻及之后 lease 即失效。
- **R15：** 心跳和结果必须携带 `attempt_id` 与 `lease_token`；不匹配或已过期返回 `STALE_LEASE`，不更新任务状态或结果。
- **R16：** Lease 过期的非终态任务重新排队。旧 worker 的迟到成功不能盖过新 attempt 的状态；达到次数上限时适用 R18。

## 结果、重试与取消

- **R17：** 同一有效 attempt 的相同结果重复提交返回原确认；不同结果返回 `RESULT_CONFLICT`。确认丢失后的重试不能再次执行终态转换。
- **R18：** 至多领取 3 次，首次计入次数。第三次 lease 过期或可重试失败之后进入 `failed`，`error_code=ATTEMPTS_EXHAUSTED`，不再派发。
- **R19：** 可重试失败不直接发布终态；仍有次数则返回 `queued`。不可重试失败立即进入 `failed`。
- **R20：** Worker 收到 `cancel_requested` 后应停止工作并确认取消；确认必须使用当前有效 lease。无法证明旧 attempt 已停止，不代表它仍有权提交结果。
- **R21：** 领取结果带 `protocol_version=1`。服务器拒绝不支持的协议版本，返回 `UNSUPPORTED_PROTOCOL`，不改变任务。

## 独立协议验收

**R22：** 外部提供方使用独立 conformance suite 验收协议，不能仅测试服务器自带 worker。两个外部提供方均须能够据此验证其依赖的接口。

| 要求 | 必须覆盖的情境 |
|---|---|
| R13–R14 | 完整领取字段；重新领取的 attempt 改变；心跳按服务端当前时间续期；到期前、恰好到期、到期后。 |
| R15–R16 | 错误 attempt/token、过期心跳与结果均为 STALE_LEASE 且无状态/结果副作用；过期重新排队；旧成功晚于新 attempt 不覆盖新状态。 |
| R17 | 相同结果重放返回原确认；不同结果冲突；模拟确认丢失重试，终态转换只提交一次。 |
| R18–R19 | 首次计数，前两次可重试失败或过期重新排队；第三次分别覆盖过期及可重试失败，均失败且不再派发；不可重试失败立即终止。 |
| R20 | 当前有效 lease 确认取消；旧 attempt 无法凭“仍在运行”继续提交；取消请求到确认之间不虚报已停止。 |
| R21–R22 | 版本字段与不支持版本的错误/无副作用；独立 suite 对外部 worker 验证上述边界、迟到、重放、冲突、耗尽语义。 |

协议传输编码、结果相等定义和部分错误优先级仍需明确；补充定义前不把推测视为当前要求。
