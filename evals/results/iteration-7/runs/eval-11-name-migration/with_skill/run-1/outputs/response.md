The seven-skill APEX series treats both phrases as pre-consolidation workflow names and translates their intent through `using-apex`; it does not load them as separate skills.

- `brainstorming` routes to `shaping-solutions`. That leaf is used only if unresolved intent, competing designs, or a useful durable implementation plan actually triggers it. It resolves material choices and obtains the needed approval before implementation; an already settled, mechanical change can skip it.
- `subagent-driven-development` expresses delegated-development intent and routes to `coordinating-subagents` when delegation is authorized and an approved plan has bounded tasks that genuinely benefit from parallelism, context isolation, or independent review. Otherwise execution stays inline. Delegation itself grants no mutation or external authority, and the controller remains responsible for scope, integration, inspecting the real diff, and final verification claims.

So “then” describes the possible order—shape the solution first, then coordinate bounded implementation—not a mandatory two-skill pipeline. APEX re-evaluates each current leaf's trigger and preserves existing authority boundaries. Because the old skill directories were intentionally deleted to keep APEX to seven skills, direct runtime lookup of either old name is a documented breaking migration. APEX must not recreate alias skills or claim that such a lookup succeeded; prompts should use `shaping-solutions` and, where delegation is actually warranted, `coordinating-subagents`.
