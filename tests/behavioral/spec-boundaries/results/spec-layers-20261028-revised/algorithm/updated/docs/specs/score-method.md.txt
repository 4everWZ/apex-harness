# score-method v2

本文拥有 Sentinel 检测器的当前方法合同及设备 SDK 方法兼容性验收；承接 M01–M18 及已接受的 v2 变更。以下 M 编号沿用输入要求标识，其窗口、warmup 和验收定义以本文 v2 内容为准。数值优化必须保持本方法语义。

## 输入、输出与每流状态

输入为 `(stream_id, event_id, timestamp, x)`，有效的 `x` 为有限实数。成功输出必须包含 `stream_id`、`event_id`、`score`、`anomaly`、`warmup_remaining`，不得省略 warmup 状态（M01）。具体类型与序列化接口尚待确定，不能借此改变以下行为。

每条流独立拥有（M02、M08、M10–M11）：

- 最多 W=128 个已接受值的有序窗口，最旧值在前。
- 上一条已接受输入的 timestamp；空状态没有上一条时间。
- 最近 128 个已接受 event_id 的 FIFO 去重记录，记录事件的 timestamp、数值和原始成功输出。

不同流不得共享窗口、均值或去重状态；相同 event_id 在不同流独立解释。错误输入不成为已接受输入。

## 新事件的评分与更新

令 `n` 为插入当前 `x` **之前**的窗口长度。评分完成后才插入当前有效值；长度超过 128 时移除最旧值。不得提前将当前值用于本次均值、标准差或分数（M03）。

当 `n < 32`（M04）：

```
score = null
anomaly = false
warmup_remaining = 32 - n
```

本次有限且有效输入仍插入窗口。因此，从空状态开始，第 32 次新接受输入使用 `n=31`，输出 `warmup_remaining=1`；第 33 次使用 `n=32`，进入评分且 `warmup_remaining=0`。不按更新后的窗口长度计算 warmup。

当 `n >= 32`，`warmup_remaining=0`，其余输出按下式确定（M05–M07）：

```
mu = sum(v for v in prior_window) / n
sigma = sqrt(sum((v - mu)^2 for v in prior_window) / n)
score = abs(x - mu) / max(sigma, 0.001)
anomaly = (score > 3)
```

标准差使用总体分母 `n`，不得使用 `n-1`。不得将 epsilon 加到 sigma 上，也不得在标准差计算前采用不同的方差截断。`score=3` 时不报异常。

单条有效输入的数值输出绝对误差不得超过 `1e-9`；误差容许不授权改变 anomaly 的布尔结果，不得用近似方差改变该结果（M15）。

## 顺序、重放与错误

| 情况 | 结果 | 状态影响 |
| --- | --- | --- |
| `x` 为 NaN、正无穷或负无穷 | `INVALID_VALUE` | 不改任何状态，不消耗 warmup（M09） |
| 同流 event_id 仍在去重记录中，timestamp 与数值均相同 | 返回该事件原始成功输出 | 不再次插入窗口，不刷新 FIFO；即使此后流状态变化，也不重新计算输出（M10–M11） |
| 同流 event_id 仍在记录中，timestamp 或数值不同 | `EVENT_CONFLICT` | 不改状态（M10） |
| 普通新事件 timestamp 小于上一条已接受输入 | `OUT_OF_ORDER` | 不改窗口、去重状态或最后时间（M08） |
| 普通新事件 timestamp 等于或大于上一条已接受输入，且输入有效 | 按本规范评分并接受 | 插入窗口，更新最后时间，追加原始输出及事件信息到 FIFO；超过 128 个时淘汰最旧记录 |

保留记录的相同事件重放必须返回原输出，不因该事件时间早于后来已接受事件而变成逆序错误。event_id 被淘汰后不再保证重放，按普通新事件处理并接受时间检查（M11）。上表不为同时违反多个检查的输入指定尚未接受的错误优先级。

## 批处理、重置与恢复

- 批输入按数组顺序逐条执行，不预排序；每一条使用此前已成功更新的状态。单条错误不回滚其他成功输入，禁止先把整个批次写入窗口再评分（M12）。
- `reset(stream_id)` 清空该流的窗口、最后时间和去重状态，不影响其他流（M13）。
- 保存与恢复必须保留窗口顺序、最后时间、去重 FIFO 以及事件原始输出；恢复后继续输入的结果必须与不中断执行一致。快照格式尚未选定（M14）。

## 方法兼容性验收

验收应核对输出和后续状态影响，覆盖正常、重放与错误路径；下表要求不指定实现语言或测试框架。

| 依据 | 输入或场景 | 必须满足的结果 |
| --- | --- | --- |
| M16 / 向量 A | 已有 32 个依次交替的 `-1,+1`，当前 `x=3` | `mu=0`、`sigma=1`、`score=3`、`anomaly=false`；当前值未提前参与统计 |
| M17 / 向量 B | 已有 32 个 `0`，当前 `x=0.004` | `score=4`、`anomaly=true`；零标准差不产生 null 或无穷 |
| M04、M18 | 从空状态跨第 32/33 次新输入 | 第 32 次仍 warmup，剩余 1；第 33 次可评分，剩余 0 |
| M02–M03、M18 | 跨第 128/129 个已接受值 | 第 128 个先用此前 127 值评分；第 129 个先用此前 128 值评分，随后移除第 1 个值 |
| M10–M11、M18 | 在状态继续变化后重放保留事件；再接受新事件；同 id 改 timestamp 或数值 | 重放返回原输出且不改变后续结果；冲突报错且状态不变 |
| M11、M18 | 接受第 128/129 个唯一 id；期间重放旧 id | FIFO 满后淘汰最旧 id；重放不刷新保留顺序；淘汰 id 再来接受普通时间检查 |
| M02、M13、M18 | 交错多流，包含相同 id、单流 reset | 窗口、均值、时间和去重隔离；reset 仅影响目标流 |
| M08–M09、M18 | 相同 timestamp、逆序、NaN、正负无穷及冲突 | 相同时间允许；错误不变状态且不消耗 warmup，可用后续相同输入序列对照验证 |
| M12 | 同批交错成功、错误、重放 | 严格按数组顺序；成功保留；每个事件使用当时状态 |
| M14、M18 | 包含窗口淘汰和去重记录的状态保存后恢复，再接续输入与重放 | 与不中断执行一致，原输出和 FIFO 顺序均保留 |
| M05–M07、M15 | 数值与阈值边界、优化后的实现 | 数值误差符合界限，anomaly 与规定公式一致 |
