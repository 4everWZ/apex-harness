# Relay 公共任务 API v2

本文件维护已接受的当前 API v2 行为与验收要求（R01–R12，含所有者已接受的 API 变更）。当前幂等窗口为 72 小时，列表同时间按 job_id 降序，其余公共 API 行为不变。HTTP 路径、方法、认证承载方式及完整 wire schema 尚未约定；下述语义是实现必须满足的契约，不将未定接口细节当作已接受定义。

## Tenant 与创建

- **R01：** 调用者只能读取和创建自己 tenant 的任务。跨 tenant 查询与不存在任务统一返回 404，不泄露任务存在性。
- **R02：** 创建必须提供 `job_type` 与 JSON `payload`。`job_type` 必须是该租户允许的已注册类型；未知类型返回 422，且不创建任务。
- **R03：** 创建请求必须携带 `Idempotency-Key`，长度为 1–128 个 ASCII 字符。缺失或格式不合法返回 400，不产生任务。

## 幂等语义

- **R04：** 幂等范围为 `tenant + key`。首次创建后的 72 小时内，同 key、同规范化请求重放必须返回同一 `job_id` 和原创建响应，不重复创建。不同 tenant 可以独立使用相同 key。
- **R05：** 同一范围与窗口内，同 key、不同请求返回 409。比较基于解析后的 JSON 结构，忽略对象键顺序，保留数组顺序；整数 `1` 和浮点 `1.0` 视为相同数字。

## 状态与取消

| 状态 | 约束 |
|---|---|
| `queued` | 首次创建的状态；领取成功之前不能记为 running |
| `running` | 领取成功才进入此状态 |
| `succeeded` | 成功终态 |
| `failed` | 失败终态；不可重试失败进入此状态 |
| `cancelled` | 取消终态 |

**R06–R07：** 状态集合仅含上表五种；后三种为终态，不得回到非终态。成功或不可重试失败分别进入相应终态。重试及次数耗尽的具体转换由 worker protocol v1 定义。

- **R08：** 取消 queued 任务立即进入 cancelled。取消 running 任务只登记取消请求，worker 确认后才进入 cancelled；不得在确认前虚报工作已停止。
- **R09：** 取消请求与成功结果并发时，以服务端先成功提交的终态转换为准；后到结果不能改写终态。重复取消必须幂等。

## 读取与列表

- **R10：** 获取任务返回 `job_id`、`job_type`、`state`、`created_at`、`updated_at`、`cancel_requested`。终态失败还返回 `error_code`。不得返回 worker stack 或 credentials。
- **R11：** 列表按 `created_at` 降序排列，同时间以 `job_id` 降序打破平局。使用不透明 cursor；`page_size` 为 1–100，游标无效返回 400。列表不得混入其他 tenant 数据。

## API 独立验收

**R12：** 幂等和终态必须通过并发请求验收，单次 happy-path 示例不足以验收 API v2。最低覆盖：

| 范围 | 必须观察的结果 |
|---|---|
| R01–R03 | 自己 tenant 的读取和创建；跨 tenant 与不存在对象均 404；未知类型 422；key 缺失、非 ASCII、长度 0 或大于 128 返回 400；拒绝创建不留下任务 |
| R04–R05 | 同 tenant/key 并发同请求只创建一个任务并重放原响应；不同请求 409；对象键序变化、数组顺序变化、1 与 1.0 的比较；不同 tenant 相同 key 独立；72 小时窗口内重放，包含首次创建后超过 24 小时且少于 72 小时的相同请求重放及不同请求冲突 |
| R06–R09 | 首次 queued、领取后 running、成功与失败终态；queued 取消立即生效；running 取消在确认前保持运行状态；取消与成功并发只保留先提交的终态；重复取消幂等，迟到结果不能改写终态 |
| R10–R11 | 返回必需字段与失败 error_code；敏感信息排除；created_at 降序、同时间 job_id 降序，含同时间任务跨页边界；page_size 边界；不透明及无效 cursor；翻页 tenant 隔离 |

这些检查尚无执行结果。缺少 wire 定义或待澄清边界时，先明确契约细节再形成可执行用例，不自行填入接受标准。
