# Relay 任务 API v1 规范

本文件拥有公共 API v1 的任务行为和验收要求（R01–R12）。

## 隔离与创建

- **R01：** 调用者只能读取和创建自己 tenant 的任务。跨 tenant 查询与不存在任务统一返回 404，不泄露存在性。
- **R02：** 创建需要 `job_type` 与 JSON `payload`。`job_type` 必须为租户允许的已注册类型；未知类型返回 422，不创建任务。
- **R03：** 创建请求必须带 `Idempotency-Key`，长度为 1–128 个 ASCII 字符；缺失或格式错误返回 400，不产生任务。
- **R04：** 幂等作用域为 `tenant + key`。首次创建后 24 小时内，同 key、同规范化请求重放，返回同一 `job_id` 及原创建响应，不重复创建。不同 tenant 可独立使用同 key。
- **R05：** 同作用域、同窗口内，同 key、不同请求返回 409。比较解析后的 JSON 结构：忽略对象键顺序，保留数组顺序，整数 `1` 和浮点 `1.0` 视为相同数字。

## 状态与取消

**R06：** 状态为 `queued`、`running`、`succeeded`、`failed`、`cancelled`。后三者为终态，不允许回到非终态；后到结果不能改写已提交终态。

| 要求 | 条件 | 状态效果 |
|---|---|---|
| R07 | 首次创建 | `queued` |
| R07 | 成功领取 | 才进入 `running` |
| R07 | 成功或不可重试失败 | 分别进入 `succeeded` 或 `failed` |
| R08 | 取消 `queued` 任务 | 立即进入 `cancelled` |
| R08 | 取消 `running` 任务 | 只登记取消请求，worker 确认后才进入 `cancelled`；不能虚报已停止 |
| R09 | 取消与成功结果并发 | 以服务端先成功提交的终态转换为准，后到结果不能改写终态 |
| R09 | 重复取消 | 幂等 |

## 查询与列表

- **R10：** 获取任务返回 `job_id`、`job_type`、`state`、`created_at`、`updated_at`、`cancel_requested`。终态失败另有 `error_code`；禁止返回 worker stack 或 credentials。
- **R11：** 列表按 `created_at` 降序，同时间按 `job_id` 升序打破平局。使用不透明 cursor；`page_size` 范围 1–100；无效游标返回 400；任何页面不得混入其他 tenant 数据。

## 验收

| 要求 | 验收情境与结果 |
|---|---|
| R01–R03 | 同租户读取/创建；跨租户和不存在查询均为 404；未知类型 422；key 缺失、0/129 长度及非 ASCII 输入为 400，错误创建无任务副作用；1/128 长度有效边界。 |
| R04–R05 | 窗口内重放响应及 job_id 相同；跨租户相同 key 独立；对象键重排、`1`/`1.0` 同请求；数组顺序改变或内容改变为冲突 409。 |
| R06–R09 | 验证状态流转、queued 取消、running 请求与确认分离、重复取消，以及已提交终态不可被后到结果覆盖。 |
| R10 | 检查所有必需字段、失败 error_code，以及 stack/credentials 不泄露。 |
| R11 | 同时间任务排序、多页边界、page_size 的 1/100 边界、无效 cursor、租户隔离。 |
| R12 | 并发相同 key 创建应只创建一次；并发不同请求复用 key 应产生冲突；取消与成功结果竞争覆盖不同提交先后次序；单次 happy-path 不能代表全部验收。 |

尚未定义的 HTTP 路径、响应编码等不由本文件自行补定；确定后应在本规范中补充，保持上述已接受语义。
