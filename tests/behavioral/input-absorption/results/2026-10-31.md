# Input ownership review — 2026-10-31

The final distinction is information ownership: a product SRS normally feeds the maintained specification; still-needed external task instructions and reference information need not become part of that specification. A useful complete original may be retained as source material. Neither the existence of `docs/inputs` nor overlap between an original and the maintained contract is itself a failure.

Current-rule executions handled ordinary absorption, useful original retention, and mixed product/task materials without a demonstrated ownership failure. These fresh-context results do not explain every decision in whale. The earlier blanket conclusion that its source copy should not exist was too strong; it has been withdrawn. The final recommendation is a one-paragraph clarification, not a prohibition on copying.

## Earlier trial and its limits

Before the source-retention distinction was clarified, an isolated V1 changed the input paragraph and added an index-self-justification sentence. Its [input paragraph](2026-10-31/candidate-trial/managing-project-docs/SKILL.md.txt) and [topology paragraph](2026-10-31/candidate-trial/managing-project-docs/references/topology.md.txt) are captured; all other candidate files matched baseline. The exact [V1 proposal](../trial-v1.md) is preserved as evaluation history, not as the recommendation.

V1's new/existing cases also preserved required semantics without original copies. Its [explicit customer-retention control](../cases/explicit-retention/task.md) retained one unchanged [signed record](2026-10-31/trial/explicit-retention/initial/docs/customer-records/signed-requirements.md.txt), alongside a separate maintained [contract](2026-10-31/trial/explicit-retention/initial/docs/specs/invoice-relay.md.txt) and unfinished plan. This demonstrates that the explicit request was honored; it does not prove that a general prohibition framed around traceability/preservation is a good rule. That wording was discarded because it could discourage useful source material whose role follows from the task without a separate copy instruction.

The final proposal differs from V1 and has not been behaviorally evaluated as candidate text. Do not report these V1 or current-rule outcomes as validation of the final wording or as a causal fix.

## Why the earlier diagnosis and coverage were insufficient

The current input paragraph at `skills/managing-project-docs/SKILL.md:23` says to consume baselines and limits rewriting, annotating and synchronizing sources. It leaves implicit the distinction between absorbing a product contract, preserving non-product instructions, and retaining an original for reference. General ownership rules already constrain unnecessary files; this review did not establish that a particular sentence caused whale's choice.

The supplied explanation for whale identifies source-reference and version-management purposes. Its plan also referred to checking delivery against the original exercise. These support a possible distinct source role. Git exclusion alone would not justify a copy, and a later README statement alone cannot prove necessity; conversely, documenting a useful source in README does not show that the model invented its purpose afterward. The complete original execution context was not available.

Earlier `spec-boundaries/prepare.py` checks input bytes and captures non-temporary Markdown, while its review rubric already calls for semantic artifact review. It was not entirely blind to new files. However, unchanged inputs do not rule out additional copies, non-Markdown files received less detailed capture, and the rubric did not specifically exercise product requirements alongside non-product task/reference information. The current review covers those responsibilities without banning a folder name or preferring a fixed file count.

## Final recommendation and repository state

Apply only the [one-paragraph input-ownership clarification](../proposal.md) if the revision is accepted: absorb the accepted system/algorithm contract, preserve still-needed external task/reference material in its proper role, and retain a complete original when that original itself is useful. Do not automatically turn SRS files into archived inputs, promote every accepted task condition into product specification, or require all non-product details to remain in a work plan.

No new topology rule, directory mandate, retention field, approval step, template or validator is recommended. Existing maintained SRS/README owners, specification layers, unresolved drafts, evidence boundaries, plan/handoff retirement and genuine recovery protection remain intact.

Local report links and capture/source correspondence were checked. These structural/integrity checks do not substitute for the independent semantic review. Formal skills, installed copies and whale were not modified. Useful fixtures and comparison evidence are retained; the current run's disposable workspace was cleaned. No commit or push was created.
