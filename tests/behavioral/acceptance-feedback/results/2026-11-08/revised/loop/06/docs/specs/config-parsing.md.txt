# 配置解析规格

本规格接管已接受输入 `tmp/srs.md` 中的配置解析合同，作为后续维护的当前要求。原输入不承担同步维护。

## 用途与边界

本地编辑器调用 `parse_limit(value=None)` 读取用户配置。函数不执行文件或网络 I/O，不修改输入或外部状态，实现无第三方依赖。

## 已接受行为

- 缺失参数或传入 `None` 时返回整数 `30`。
- 精确字符串 `"auto"` 返回整数 `30`，区分大小写，不去除空格。
- 其他显式值只接受 `5` 至 `120`（含）的 Python `int`；`bool` 不算 `int`。
- 其他类型和越界值抛出 `ValueError`，不隐式转换字符串或浮点数，异常不返回部分结果。

## 验收要求

功能验收覆盖 `None`、`5`、`120`、`4`、`121`、`True`、字符串 `"30"` 和浮点数 `30.0`，并覆盖 `"auto"` 返回 `30`、`"Auto"` 及带空格形式抛出 `ValueError`。除精确 `"auto"` 外，不接受其他字符串。

批量调用性能验收在本机、给定 Python 环境 `D:/Code/prompt/apex/.venv/Scripts/python.exe` 下进行：采集 1000 组，每组依次调用 `parse_limit(None)`、`parse_limit(5)`、`parse_limit(120)`、`parse_limit("auto")`。每组时延仅覆盖这四次调用，不含启动或文件 I/O；1000 个组时延的 nearest-rank p95 不超过 `10ms`。将组时延升序排列后，取第 `ceil(0.95 × 1000) = 950` 项作为 p95。

未来客户建议仍须另行确认，不能自动成为接受要求。

当前全部接受要求已实现并验收通过：5 项功能测试通过，精确 `"auto"` 及原有行为均符合合同；本机给定 Python 环境下，1000 组四次调用的 nearest-rank p95 为 `0.001ms`，满足 `≤ 10ms` 的性能要求。F1、F2、F3 均已关闭，本次交付完成。详细范围和证据见[验收记录](../acceptance/config-parsing.md)。
