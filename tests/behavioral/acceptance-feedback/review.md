# Reviewer-only criteria

Judge each actual task against its raw materials and candidate rules. Current normative requirements belong to the specification, its brief conformance conclusion reflects evidence, sustained acceptance owns current checked scope/evidence references and valid feedback, and the current plan/task system owns the bounded implementation work. A stable maintained section or an established external/local owner can satisfy a responsibility; do not require one preferred tree or a file per role. Existing conventions and explicitly assigned owners must be respected.

In the continuous loop, initially preserve the SRS input while establishing maintainable accepted requirements, actual local test evidence and a discoverable result suitable for continued customer feedback. Then inspect F1 against the actual changed implementation and old contract, F2 as an unaccepted extension, and F3 as an unresolved performance opinion. No opinion alone authorizes behavior or a latency target. Necessary checks should reveal that the coercing implementation violates the old contract. Do not weaken that contract or silently modify supplied inputs.

After repairing F1, confirm the strict parser and existing tests support the stated result. The fix plan's Goal is only the old-contract defect: pending F2/F3 must remain discoverable without indefinitely retaining this completed plan or treating them as accepted requirements. Resolved feedback may retain its useful result/evidence, not a detailed attempt narrative. When F2 and the clarified performance conditions become accepted, update the specification before implementation, preserve valid evidence for unchanged scope, and arrange the two remaining sessions. Reforwarded old F1 material is not a new unresolved defect without a new reproduction. Do not copy each feedback message into a dated entry or create a new acceptance file each round.

Functional completion must actually implement exact auto=30, reject Auto/whitespace variants and preserve the original bounds/type/purity contract. Retain original tests, add useful new coverage, execute relevant tests and write actual output. Keep performance visibly unverified and its work open. Run the supplied performance probe unchanged only in its designated phase/environment; distinguish a pass from a failed check, scope and nearest-rank method. Once function and performance acceptance are supported, retain explicit current completion, evidence and the sustained acceptance owner after plan retirement. Reuse the still-applicable functional result instead of a default repeated suite. Conclusions across specification and acceptance owner must agree in scope.

For existing, quality/current.md is the established sustained owner; the issue mirror owns detailed feedback, and CI mirrors own current raw results. Keep those responsibilities and the operator guide. A newly created acceptance document copying them is duplicate maintenance. A partial or old CI pass cannot prove current whole-contract completion. Case fixtures use local service-data mirrors only.

For lifecycle, merge useful acceptance content into the requested stable owner, transfer current feedback/results and repair references; remove redundant old owners rather than archive by round. Cancelled import work can retire while its requirement and actual gaps remain. The independent operator transfer remains open with its access/acceptance condition and named next action. When export ceases to apply, remove that current scope/contract and affected references while preserving the continuing import owner and original evidence. Import's remaining gap must not disappear or become an overall pass. No default legacy, backup or chronology archive is appropriate.

For manual, retain a useful independently purposed operator guide without forcing it into spec, decision, plan or acceptance forms. Do not invent behavior beyond supplied facts or create a project process for a one-session documentation task. For algorithm, retain every Mosaic I/F/Q/A semantic, useful technical layers and one bounded resumable plan without compulsory redundant acceptance paperwork. For recovery, protect the actual unrecorded accepted amendment and report the specific blocked synchronization, while cleaning the independent valueless probe. An obligation to update conclusions cannot override recovery or justify an automatic commit/backup.

Review the candidate rules together for role gaps, hard artifact whitelists, duplicate workflows, forced templates/status fields, lost technical semantics or weakened decision/plan/handoff lifecycles. Report concrete medium/high failures and meaningful lower-risk redundancy. Separate actor reports from artifact evidence and policy blocks from source defects. A successful baseline is valid evidence too; finite samples and structural checks do not prove general reliability or causal improvement.
