# Current specifications and material gaps: 2026-11-08

## Change

Specifications remain accepted normative contracts. They now point to the existing owner of important implementation/verification gaps, or carry a brief descriptive notice when no other artifact owns that state. Notices are updated or removed, not accumulated as progress history. Absence of a plan is explicitly not proof of conformance.

Accepted changes update the canonical specification in place; the default legacy path, generations, predecessor copies, retention fields and specification lineage are removed. History is retrieved from Git, without adding revision hashes or historical navigation to specifications. The shared recovery protection remains limited to content that still needs preservation, including actual accepted content not recorded in Git. Decision-record succession and the distinction between delivery, cancellation and transfer remain intact.

Source changes are limited to the specification lifecycle, topology, one tracking phrase in the working-document lifecycle, and the repository README. Sparse links now allow a material gap's owner and reject back-links added merely for symmetry; otherwise an existing blanket prohibition would conflict with legitimate spec-to-status-owner and plan-to-contract references. No APEX policy, entrypoint, template, schema, matrix requirement or validator rule was added or changed. The tracked source diff removes more lines than it adds; line count is not behavioral acceptance evidence.

## Method

Seven fresh-context executors actually maintained isolated projects across nine task stages. Only skill-creator was activated; the documentation skill and its resources were candidate material. Each actor received its task, candidate and raw project, not the suspected issue, proposed edits, expected layout, review criteria, other cases or previous conclusions. Only the existing-gap actor could run the fixture's existing unittest suite, using the repository's existing Python environment without installations. The same actor continued that case after each capture and supply of the next stage's raw material.

One additional fresh-context reviewer inspected the retained artifacts, raw tasks, candidate resources and root README. It did not inspect the live projects or earlier reports. The [case index](../README.md) explains setup, including initial local commits in the three recovery fixtures and the uncommitted amendment in behind. These setup commits are not commits in the main repository. Candidate resources are preserved under `2026-11-08/candidate/` with `.txt` suffixes; task-stage captures retain original relative paths and omit fixture Git directories, caches and tool transcripts.
