# Relay 开发与验收工作计划

**目标：** 分会话实现并验收 Relay 已接受的 API v1、worker protocol v1、audit format v1 及跨边界一致性。

**主契约：** [Relay 产品规范](../specs/relay.md)，含三个详细接口规范的入口。

当前尚无应用实现，亦无任何实现符合性证据。本次仅完成文档准备；不安装依赖、不运行实验、不部署。不修改传入的 `tmp/product-srs.md`，后续契约维护由规范承担。

## 待定事项与下一步

下一步为项目所有者与实现者明确以下问题；本计划仅列出缺口，不替其选择答案。未决项阻止相应接口的完整互操作实现或验收，不撤销已接受的要求。

| 范围 | 需明确的内容 |
|---|---|
| API 线协议 | 路径/方法、tenant 身份来源及鉴权、请求/响应编码、创建及取消响应、错误体、字段类型与时间表示、分页封装和游标边界；page_size 缺省及越界错误处理 |
| API 幂等 | 24 小时精确边界及窗口后 key 复用规则；键的 ASCII 范围是否排除控制字符；完整规范化请求的字段范围、无效 JSON/重复键处理；并发和重启下原响应的保存方案 |
| Worker 线协议 | 领取/心跳/结果/取消确认的消息结构与传输、worker 权限与 tenant 绑定、可重试/不可重试结果编码、结果相等规则和确认结构、版本协商入口 |
| Worker 交互边界 | 终态结果重放与失效 lease 检查的优先级；取消请求遇到 lease 过期或可重试失败后如何继续传递；终态后的 lease/心跳处理。保持旧 attempt 无权提交和终态不可改写 |
| 审计定义 | kind 枚举字面值及各转换对应关系、actor_type/actor_id 定义、字段类型、事件身份与序号分配规则；重复取消是否产生新事件的条件 |
| 审计传输 | format_version 和 next_sequence 的承载位置、请求/响应封装、空批次 next_sequence、空导出的字节表示；保证有事件时仍逐行完整 JSON 并以换行结束，不用数组替代 |
| 技术设计 | HTTP 框架、数据库、队列是否需要及其选择、部署方式；任务/幂等持久化、租约时间源及并发提交方案、状态与审计的事务或 outbox 恢复机制 |

重大选择或契约补充须遵循项目所有者的接受流程。只有当某项选择及其理由确需独立维护或引用时再建立决策记录；不为尚未讨论的选项预建记录。

本计划在实现与实际验收完成、契约同步后结束；仅完成文档或写出代码不足以关闭。当前没有实际责任转移，因此不另建交接文档。
