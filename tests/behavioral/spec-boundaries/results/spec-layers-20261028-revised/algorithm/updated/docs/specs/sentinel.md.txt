# Sentinel 项目规范

Sentinel 是流式异常检测项目。本规范及其技术层承接 `tmp/method-brief.md` 中的 M01–M18、E01–E12，以及 `tmp/accepted-method-change.md` 中已接受的方法 v2 变更的持续维护职责。传入材料保持为只读基线，不承担项目规范维护。

## 范围与规范所有权

| 规范 | 所有内容 | 消费者 |
| --- | --- | --- |
| 本文 | 项目范围、共享约束、方法与评测的组合关系 | 项目实现与验收参与者 |
| [score-method v2](score-method.md) | 检测器输入输出、状态、公式、错误与恢复语义，以及方法兼容性验收 | 检测器开发者、设备 SDK 组 |
| [evaluation protocol v3](evaluation-protocol.md) | 数据隔离、指标、计时、比较与报告口径，以及评测器验收 | 离线 QA 工具维护者、评测人员 |

方法与评测协议具有独立的接受和替换周期。方法实现可以在保持语义的前提下优化；算法改版不会自动更改 evaluation protocol v3，QA 比较口径必须保持可比较。变更哪个合同，应同步更新其拥有规范并取得相应接受。

## 共享约束与组合验收

- 当前方法为 score-method v2，评测协议为 evaluation protocol v3；评测的精确参考实现对应当前方法 v2。设备 SDK 的方法兼容性与 QA 评测协议独立验收，最后还必须验证检测器与评测器组合口径一致（E12）。
- 组合验收须检查检测器输出的事件身份、warmup、错误和重放语义与评测器的标签对齐、排除和唯一事件计数相容；各组件独立通过不能代替这一检查。
- 项目所有者尚未选定语言、框架、模型依赖；本规范不作选择。
- median/MAD 仍为未接受的研究设想，不属于当前合同。方法 v2 获接受不构成效果或性能提升的证明。
- 实现、测试或实验产生的行为不会自动成为规范。文档记录要求，不构成已实现、已验收或达到性能目标的证据。
