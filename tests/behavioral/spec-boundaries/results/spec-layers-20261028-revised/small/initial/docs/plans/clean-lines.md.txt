# clean-lines 开发计划

目标：跨两个开发会话实现并验收供本地编辑器调用的 clean-lines。当前仅完成开工文档，尚无实现，也未运行实现或验收。

契约由 [clean-lines 规格](../specs/clean-lines.md) 维护。所有者已接受的 [传入要求](../../tmp/requirements.md) 仅为输入基线，保持原样，不承担后续同步。

## 待办与恢复点

1. 开工时确定项目语言、依赖管理和编辑器实际调用方式，补充相应运行说明。当前未指定语言或依赖，不预先锁定。
2. 在涉及相应行为前澄清下列输入边界；获接受后更新规格，避免将实现默认值自动升级为契约。
3. 第一开发会话：按规格实现参数解析、严格 UTF-8 读取及文本变换，确保错误情况下不提前写 stdout。建立覆盖规格验收表的检查，记录实际完成项和剩余项，供第二会话恢复。
4. 第二开发会话：完成剩余实现与验收，核对 C01–C10，重点检查 CRLF、空格行、非 ASCII code point 排序、reverse 和非法输入的 stdout 原子性。记录实际证据位置和未通过项，不以文档检查代替行为验收。
5. 实现与验收完成后，确认已接受的变更均同步到规格；达到本计划目标后按项目规则退休本计划。

## 待澄清边界

- EOF 前没有 LF/CRLF 的非空尾段是否作为最后一行。
- 单独 CR 和输入开头 UTF-8 BOM 的含义：作为文本保留，还是有特殊处理。
- 重复 `--reverse` 的处理方式。当前契约仅规定该选项的排序语义。

这些问题未改变已接受要求；基础成功与失败路径可按规格推进。不存在待批准的架构选型或独立模块发布方案，也没有需要另建交接文件的责任转移。
