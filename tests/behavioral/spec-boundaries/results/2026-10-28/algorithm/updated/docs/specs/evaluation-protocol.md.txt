# Sentinel evaluation protocol v3

本文件承接已接受的评测要求 E01–E12，持续维护离线 QA 工具的评测契约。协议与 score-method 的接受和替换周期独立；方法优化或改版不自动改变本协议。按已接受的参考方法变更，质量基准为精确 score-method v2；其行为由 [score-method 规范](score-method.md) 定义。协议仍为 v3，切分、质量指标和延迟统计定义保持不变。

## 数据切分与泄漏防护

- **E01**：输入标注集按每条流的时间顺序，逐流划分 train/validation/test，比例为 60%/20%/20%，切点向下取整。不足样本的流计入排除数。不足样本的具体判定标准尚未选定，正式可比较评测前必须明确，不得自行以某个最小长度替代。
- **E02**：train 可用于确定候选实现参数，validation 用于选型。test 只作最后一次对外比较，不得根据 test 标签调整阈值或选择变体。
- **E03**：各切分区间从空检测器状态开始，彼此不得共享窗口或去重状态。warmup 输出不计入质量指标，但必须报告被排除数量。

## 标签与质量

- **E04**：质量为各流 F1 的宏平均，不能替换为全体事件 micro F1。对于每条参与评测的流，通常的 F1 为 `2TP/(2TP+FP+FN)`；无正例且无预测正例时定义为 1，有正例但零命中时为 0。
- **E05**：标签按输出对应的 event_id 对齐，不按批位置；重复事件输出按唯一 event_id 只计一次。流内唯一性遵循方法的 stream_id 隔离。错误输入不当作负例。
- **E08**：质量不得劣于精确 v2 参考实现。当前没有质量测量或符合性证据。

## 延迟

- **E06**：固定 host H1、固定单线程、`batch=1`。计时包含 score 计算与窗口/去重状态更新，不包含数据加载、进程启动、快照写入或评测汇总。
- **E07**：warmup 后的有效唯一事件构成延迟样本。对 N 个样本从小到大排序，p95 为第 `ceil(0.95*N)` 个样本，索引从 1 开始，不作线性插值。N=0 时报告 `unavailable`，不得写 0。
- **E08**：p95 目标为不高于 2 ms。当前没有速度测量；目标不是已达到的事实。

## 比较与报告

- **E09**：主机、线程、批大小、数据集、切分或 warmup 规则不同的结果，不得宣称为同条件算法提升。
- **E10**：报告包含各切分的有效流数、有效事件数、排除原因、质量汇总和延迟样本量。逐样本原始结果归评测输出目录所有，不在本规范积累运行日志。
- **E11**：评测器验收独立检验切分边界、泄漏防护、宏平均特殊值、标签对齐、warmup 排除和 nearest-rank 分位数。检测器单元测试不得替代评测协议验收。
- **E12**：设备 SDK 的方法兼容性与 QA 协议独立验收；最后还须检验检测器与评测器组合口径一致。

## 协议验收要求

| 范围 | 验收所需观察 |
|---|---|
| E01–E03 | 逐流切分边界及取整、排除计数、train/validation/test 用途隔离、各区间空状态启动；防止窗口或去重状态跨区间泄漏。 |
| E03–E05 | warmup 的排除与计数；逐流 F1 后宏平均，覆盖无正例且无预测正例、有正例但零命中；标签按 event_id 对齐，重复只计一次，错误不作负例。 |
| E06–E07 | 固定执行条件及计时边界；只采集 warmup 后有效唯一事件；覆盖 ceil 索引、无插值和空样本 unavailable。 |
| E08–E10 | 质量与精确 v2 比较、p95 目标判断、比较条件记录、各切分计数与排除原因、延迟样本量和原始输出归属。 |
| E11–E12 | 独立评测器验收与独立方法兼容性验收之后，完成组合检查；不能以其中一层的结果代替另一层。 |

这份契约确立验收口径，不提供实验结果，也不声称实现已通过。
