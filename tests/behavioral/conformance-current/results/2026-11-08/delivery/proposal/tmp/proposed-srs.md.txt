# LimitParser 需求讨论 SRS

本文供客户讨论默认值调整使用。现行要求来源于[当前接受规格](../docs/specs/limit-parser.md)；“默认值改为 90”尚未接受，以下候选内容不构成当前契约。

## 产品范围与现行要求

LimitParser 提供纯函数 `parse_limit(value=None)`，无第三方依赖。

| 输入或约束 | 已接受要求 |
|---|---|
| 省略参数或传入 `None` | 返回整数 `30` |
| 精确字符串 `"auto"` | 返回整数 `30` |
| Python `int`，值在 `5` 至 `120`（含） | 返回输入整数；`bool` 不作为 `int` 接受 |
| 其他类型或范围 | 抛出 `ValueError`，不返回部分结果 |
| 字符串与浮点 | 不隐式转换为整数；`"Auto"`、带空格形式、`"30"` 和 `30.0` 均应拒绝 |
| 状态 | 不修改输入或外部状态 |

现行功能验收覆盖 `None`、`5`、`120`、`4`、`121`、`True`、`"30"`、`30.0`、`"auto"`、`"Auto"` 和带空格形式。

现行性能要求：在当前本地主机及项目 Python 环境 `D:/Code/prompt/apex/.venv/Scripts/python.exe` 上采样 `1000` 组，每组依次调用 `None`、`5`、`120`、`"auto"`。只计每组四次函数调用，不计启动或文件 I/O；按 nearest rank 取 p95，即升序排列后的第 `950` 个耗时，要求不超过 `10ms`。其他主机结果不能替代该验收。

## 候选变更：默认值 90（尚未接受）

讨论提议是把默认值从 `30` 改为整数 `90`。就省略参数及 `None` 场景而言，候选行为为：

| 场景 | 当前已接受结果 | 候选结果 |
|---|---|---|
| `parse_limit()` | `30` | `90` |
| `parse_limit(None)` | `30` | `90` |

本提议尚未明确 `"auto"` 是否也随默认值调整；其当前接受结果仍为 `30`。其他输入约束、错误语义、纯函数约束与性能要求按现行要求保留，除非客户另行提出并接受变更。

## 待客户确认

- 是否接受将省略参数及 `None` 的返回值改为 `90`？
- 精确字符串 `"auto"` 是否跟随新默认值返回 `90`，还是继续返回 `30`？

若提议获接受，需据确认范围更新接受规格及相关功能验收期望，并验证受影响行为与现行性能要求。现有验收结果支持现行契约，不代表候选变更已实现或通过验收。
