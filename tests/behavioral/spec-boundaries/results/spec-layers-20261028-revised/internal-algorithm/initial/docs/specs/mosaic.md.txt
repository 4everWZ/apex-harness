# Mosaic 整体规范

本文件及直接引用的技术规范承接所有者已接受的 Mosaic 契约。它们共同描述一个整体发布、整体验收的工具；内部技术分层不建立外部 SDK、模块版本兼容承诺或分开的团队职责。

## 范围与规范边界

Mosaic 是仅在本地主机运行的重复图片检索工具。调用者提供已经解码的像素矩阵；图片格式解码、网络服务和 GUI 不在范围内。

本文件维护输入处理、状态约束、持久性与整体验收。以下技术规范维护各自的详细定义及局部验收：

- [特征计算](image-features.md)：F01–F08，亮度、分区均值、位特征、颜色特征与精度。
- [索引与查询](index-query.md)：Q01–Q10，索引内容、查询入口、距离、筛选与排序。

A06：语言、依赖、索引结构与快照格式尚未选择，不得将未定事项写成所有者已接受的产品约束。

## 输入与状态契约

| 要求 | 已接受行为 |
|---|---|
| I01 | 图片是非空 H×W×3 的整数 RGB 矩阵，各通道值为 0–255。非法维度、非整数或越界返回 `INVALID_IMAGE`，索引状态不变。 |
| I02 | H 或 W 小于 8 返回 `IMAGE_TOO_SMALL`，不得通过复制像素或插值隐式放大输入。 |
| I03 | 每张图片具有区分大小写的 UTF-8 `image_id`。同 id、像素完全相同的重复添加返回原确认，不重建特征；同 id、不同像素返回 `ID_CONFLICT`，状态不变。 |
| I04 | 特征与确认仅从成功接受的原像素派生。不自动旋转、裁剪或做 EXIF 修正；矩阵行列顺序由调用者给出。 |
| I05 | 添加、删除、查询按调用顺序串行执行；本轮没有并发写承诺。 |
| I06 | 单图添加失败不残留部分特征或 id。批添加按数组顺序逐项执行；单项失败不回滚其他成功项。 |
| I07 | 删除不存在的 id 为幂等成功。删除已存在 id 后不得再返回其旧特征；删除后可以重新添加该 id，并按新图片处理。 |
| I08 | 不修改调用者的像素矩阵；输入返回后，调用者修改矩阵不得改变已经接受的索引内容。 |

## 持久性

A01：保存必须包含所有 id 及有效特征、输入内容身份。恢复后，添加重放、冲突、删除和查询应与不中断执行一致，不能只恢复查询结果。特征精度由 F06 约束，索引内容与内容身份由 Q01 约束。

## 整体验收

A02：除输入、特征、查询距离的独立向量验收外，还必须组合验收以下情况：

- 同像素、不同 id。
- 添加后修改调用者矩阵。
- 删除后重新添加。
- 同距离时的 id 平局排序。
- 距离恰好等于阈值。
- k 超出现有结果数量。
- 保存恢复后的添加重放。

输入验收需覆盖 I01–I08 的成功、错误和状态不变条件；技术规范中的局部验收与上述组合场景共同构成整体验收。

A03：固定主机 H1、10000 张已建索引图片、单线程、k=10 时，查询性能目标为 p95≤50ms。计时包含查询特征计算、距离计算和排序，不包含图片加载、索引保存。

A04：p95 使用 nearest rank：将 N 个样本升序排列，取第 ceil(0.95×N) 个样本（从 1 起始）。无样本应报告 `unavailable`，不得报告 0。

A05：未测量不等于性能达标。不同主机、图片集、解码条件或近似检索配置的结果不得作为同条件提升。逐次参数及原始实验结果由运行输出持有，不累积到规范。

本规范确立要求，不证明实现符合或性能达标。
