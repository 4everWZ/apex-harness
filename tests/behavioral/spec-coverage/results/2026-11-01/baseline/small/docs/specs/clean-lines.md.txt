# clean-lines 规范

## 目标与边界

`clean-lines` 是供本地编辑器调用的命令行工具，消费者通过 stdin 提供文本，从 stdout 接收清理后的文本。工具作为一个整体发布和验收；读取、过滤、排序、写出是内部步骤，共享本规范。

本文件承接所有者已接受的 C01–C10，维护当前行为、接口和验收约定。语言和依赖由实现阶段选择。

## 命令行与错误

- 调用形式：`clean-lines` 或 `clean-lines --reverse`。
- C08：成功退出 0。未知参数退出 2，stderr 提供简短提示，stdout 为空。不接受文件路径参数，不原地修改文件。
- C01：从 stdin 读取严格 UTF-8。非法 UTF-8 时退出 2，stderr 给出简短原因，stdout 必须为零字节；不能先写出合法前缀再报告解码错误。

## 文本处理

1. C02：接受 LF 和 CRLF 行分隔。每行仅去除行终止符，不去除首尾空格。
2. C03：只删除长度为零的行。仅含空格的行必须保留。
3. C04：按字符串完全相等去重，区分大小写，不做 Unicode 规范化。
4. C05：按 Unicode code point 升序排序，不使用 locale 排序。
5. C07：有 `--reverse` 时，仅反转最终排序结果；空行定义和去重规则不变。
6. C06：输出为 UTF-8，每个保留行后恰有一个 LF。空输入或过滤后无行时，输出零字节。

实现可将这些职责组织为读取、过滤、排序、写出等步骤，但整体必须满足错误时 stdout 为空的约束。

## 验收

下表的 `\n`、`\r\n` 分别表示实际 LF、CRLF 字节序列，`\xNN` 表示单字节；引号不属于输入输出。`U+XXXX` 表示实际 Unicode 字符。成功用例均须同时检查退出码 0；错误用例检查退出码 2、非空且简短的 stderr，以及 stdout 零字节。

| 要求 | 输入与调用 | 期望输出或检查 |
|---|---|---|
| C02、C03、C04、C05、C06、C09 | 默认调用，输入 `b\n\nA\nb\n \n` | 精确输出 ` \nA\nb\n`，其中空格行含一个 U+0020 |
| C02、C06、C09 | 默认调用，输入 `b\r\n\r\nA\r\nb\r\n \r\n` | 精确输出 ` \nA\nb\n`，输出不含 CR |
| C06、C10 | 默认调用，零字节输入 | 零字节输出 |
| C03、C06、C10 | 默认调用，输入 `\n\r\n\n` | 零字节输出 |
| C02、C03、C04、C10 | 默认调用，输入 ` x \nx\n x \n  \n` | 精确输出 `  \n x \nx\n`，保留行内及首尾空格 |
| C04、C05、C10 | 默认调用，依次输入 `a`、`A`、`a`，每行 LF 结束 | 输出依次 `A`、`a`，各以 LF 结束 |
| C04、C05、C10 | 默认调用，依次输入 `U+00E9`、`U+0065 U+0301`、`U+00E9`，每行 LF 结束 | 输出依次为 `U+0065 U+0301`、`U+00E9`；保留两种不同字符串，各以 LF 结束 |
| C05、C10 | 默认调用，依次输入 `U+10000`、`U+E000`，每行 LF 结束 | 输出依次 `U+E000`、`U+10000`，各以 LF 结束；验证按 code point 而非 UTF-16 码元顺序 |
| C07、C09、C10 | `--reverse`，输入 `b\n\nA\nb\n \n` | 精确输出 `b\nA\n \n` |
| C07、C10 | `--reverse`，零字节输入或纯空行输入 | 零字节输出 |
| C01、C10 | 默认调用，输入字节 `ok\n\xFF`；另验截断 UTF-8 序列 `ok\n\xC3` | 两者均报解码错误，不能输出 `ok\n` 或其他部分结果 |
| C08、C10 | 输入合法文本 `b\n`，分别传入 `--unknown` 和文件路径参数 `input.txt` | 两者均按未知参数失败，stdout 零字节 |

这些是待实现者执行的验收要求，不代表已有实现或已通过验收。
