# clean-lines 规格

本文件维护所有者已接受的 clean-lines 契约及验收要求。clean-lines 是供本地编辑器调用的命令行工具，只有一个消费者，整体发布、整体验收。内部读取、过滤、去重、排序和写出属于同一契约，不设独立技术规格。

## 命令行与错误

- 输入仅来自 stdin，无文件路径参数，不原地修改文件。（C08）
- 不带选项时执行升序处理；`--reverse` 仅反转最终排序结果，不影响过滤和去重。（C07）
- 成功退出 0。未知参数退出 2，stderr 给出简短提示，stdout 为零字节。（C08）
- stdin 必须是严格 UTF-8。非法 UTF-8 时退出 2，stderr 给出简短原因，stdout 为零字节；即使非法字节出现在有效内容之后，也不能输出部分结果。（C01）

## 文本变换

1. 接受 LF 和 CRLF 分隔；每行仅移除行终止符，不移除空格。（C02）
2. 仅删除长度为零的行；一个或多个空格组成的行必须保留。（C03）
3. 按字符串完全相等去重，区分大小写，不执行 Unicode 规范化。（C04）
4. 按 Unicode code point 的字典序升序排列：从首个不同的 code point 比较，若一行是另一行的前缀则短行在前；不使用 locale 排序。语言运行时的默认比较方式只有满足此定义时才能直接使用。（C05）
5. 如有 `--reverse`，反转上述排序结果。（C07）
6. 以 UTF-8 写出，每个保留行后恰有一个 LF，不输出 CRLF；空输入或过滤后无行时输出零字节。（C06）

错误处理必须满足上述 stdout 原子性。内部步骤与缓存、语言和依赖的选择不改变此要求。

## 验收

下表使用带引号的字符串表示输入和输出，双引号不属于数据；`\n` 为 LF，`\r` 为 CR，`\uXXXX` 和 `\UXXXXXXXX` 为对应 Unicode code point。除明确标记的非法字节外，字符串均按 UTF-8 编码。每个成功用例要求退出 0；错误用例要求退出 2、stderr 有简短原因、stdout 为零字节。

| 用例 | stdin / 参数 | 期望 stdout | 覆盖 |
|---|---|---|---|
| 基准 | `"b\n\nA\nb\n \n"` | `" \nA\nb\n"` | C02–C06、C09 |
| CRLF | `"b\r\n\r\nA\r\nb\r\n \r\n"` | `" \nA\nb\n"` | C02、C06、C09 |
| 空输入 | 零字节 | 零字节 | C06、C10 |
| 纯空行 | `"\n\r\n\n"` | 零字节 | C02、C03、C06、C10 |
| 重复与大小写 | `"b\nA\na\nb\nA\n"` | `"A\na\nb\n"` | C04、C05、C10 |
| 保留空格 | `"a \n a\n \n  \n"` | `" \n  \n a\na \n"` | C02、C03、C05、C10 |
| 非 ASCII 与规范化 | `"é\ne\u0301\né\n"` | `"e\u0301\né\n"` | C04、C05、C10 |
| code point 比较 | `"\U00010000\n\uE000\n"` | `"\uE000\n\U00010000\n"` | C05、C10 |
| 反序 | 基准输入，参数 `--reverse` | `"b\nA\n \n"` | C07、C10 |
| 非法 UTF-8 | 原始字节 `62 0A FF` | 零字节 | C01、C10 |
| 不完整 UTF-8 | 原始字节 `62 0A C3` | 零字节 | C01、C10 |
| 未知参数 | 有效基准输入，参数 `--unknown` | 零字节 | C08 |
| 文件路径参数 | 有效基准输入，位置参数 `input.txt` | 零字节 | C08 |

这些用例定义预期行为，不表示已有实现或已通过验收。其他尚未获明确规定的输入边界在工作计划中保留为待澄清项。
