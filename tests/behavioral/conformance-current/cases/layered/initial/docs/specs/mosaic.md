# Mosaic 总体规范

Mosaic 是在本地主机运行的重复图片检索工具。本规范与下列技术规范共同承接项目所有者已接受、尚未实现的要求；技术分层服务于实现和维护，工具仍整体发布、整体验收：

- [特征定义](features.md)拥有亮度、分区、位序、颜色特征及对应独立向量验收（F01–F08）。
- [索引与查询](retrieval.md)拥有索引内容、查询、排序、持久化及恢复语义（Q01–Q10、A01）。

本文件拥有工具范围、共享输入与变更语义（I01–I08）以及整体组合和性能验收（A02–A06）。后续已接受的契约变更更新各自所有者；实现工作和未定事项见[开发计划](../plans/mosaic.md)。当前没有实现或性能证据。

## 范围与共享约束

输入为调用者已经解码的像素矩阵。不包含图片格式解码、网络服务或 GUI。特征、索引与检索仅供本工具内部使用，不承诺外部 SDK、模块版本兼容发布或分开团队的交付边界。

语言、依赖、索引结构和快照格式均未选择（A06），本规范不将这些选择设为已接受约束。

## 输入与操作语义

| 要求 | 已接受契约 |
|---|---|
| I01 | 图片必须为非空 H×W×3 整数 RGB 矩阵，各通道取值 0–255。非法维度、非整数或越界值返回 `INVALID_IMAGE`，索引状态不变。 |
| I02 | H 或 W 小于 8 返回 `IMAGE_TOO_SMALL`。不得通过复制像素或插值自动放大输入。 |
| I03 | 每张图片使用区分大小写的 UTF-8 `image_id`。重复添加同 id、完全相同像素时返回原确认，不重建特征；同 id、不同像素时返回 `ID_CONFLICT`，状态不变。 |
| I04 | 特征与确认仅从成功接受的原像素派生；不得自动旋转、裁剪或执行 EXIF 修正。矩阵行列顺序由调用者给出。 |
| I05 | 添加、删除、查询按调用顺序串行执行；当前没有并发写承诺。 |
| I06 | 单图添加失败不留下部分特征或 id。批添加按数组顺序逐项执行，单项失败不回滚其他成功项。 |
| I07 | 删除不存在 id 为幂等成功。删除存在 id 后不得再返回其旧特征；删除后可重新添加该 id，作为新图片处理。 |
| I08 | 不得修改调用者的像素矩阵；输入返回后，调用者对矩阵的后续修改不得改变已接受的索引内容。 |

这些输入和特征规则同样适用于图片查询。错误名称属于契约；尚未给定的调用签名、确认结构和多项同时非法时的错误优先级由开发计划管理，不在此推定。

## 整体验收

### 功能组合（A02）

各技术规范的独立向量之外，必须组合验证：

- 相同像素、不同 id 可分别添加；使用其中一个 id 查询时另一个仍可返回。
- 添加后修改调用者矩阵，已接受内容及查询结果不随之变化。
- 删除后重加同 id，按新图片建立内容，不返回被删除的旧特征。
- 同距离候选按 Unicode code point 的 id 顺序决胜。
- 距离恰好等于门限时包含；k 大于现有合格结果数时返回全部合格结果。
- 保存、恢复后重放添加，重复确认、冲突、删除和查询与不中断执行一致。

### 性能（A03–A05）

在固定主机 H1 上，对 10000 张已建索引图片以单线程、`k=10` 查询，要求 p95≤50ms。计时包括查询特征计算与距离排序，不包括图片加载和索引保存。

p95 采用 nearest rank：将 N 个样本升序排列，取第 `ceil(0.95*N)` 个样本（从 1 开始计数）；无样本报告 `unavailable`，不得报告 0。

未测量不等于性能达标。不同主机、图片集、解码条件或近似检索配置的结果不得当作同条件提升。逐次参数和原始实验结果由已有运行输出持有，不堆入规范。H1、图片集及采样安排尚需落实，见开发计划。

### 当前适用状态（A06）

上述要求是已接受的目标契约，尚无实现或性能证据。本轮文档准备不构成算法正确性、性能或整体交付验收。
