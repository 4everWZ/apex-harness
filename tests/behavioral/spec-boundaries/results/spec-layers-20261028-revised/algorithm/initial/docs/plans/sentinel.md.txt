# Sentinel 实现与评测工作计划

目标：跨会话完成检测器实现、设备 SDK 方法兼容性、离线 QA 评测器及最终组合验收，保持 score-method v1 和 evaluation protocol v3 的独立边界。

当前合同入口为 [Sentinel 项目规范](../specs/sentinel.md)，具体实现与验收分别按 [方法规范](../specs/score-method.md) 和 [评测协议](../specs/evaluation-protocol.md)。传入基线为 [method-brief](../../tmp/method-brief.md)，已接受要求已承接至规范；原输入不改写。

## 当前状态

仅有文档；没有实现、测试、速度或质量运行证据。语言、框架、模型依赖未选定。本轮不实现、不运行实验。

## 待澄清与选择

以下事项尚未接受，不得将临时实现选择当作当前合同；涉及行为或评测口径的回答应先更新相应规范。

| 事项 | 需要的决定与影响 | 下一步 |
| --- | --- | --- |
| 事件接口 | stream_id、event_id、timestamp 的类型、比较/相等规则，错误输出结构及快照格式未给定 | 项目所有者与 SDK 消费方明确互操作接口；不得改变 M01–M14 的既定状态语义 |
| 同时触发多个错误 | 非有限值同时伴随重复 id 冲突或逆序时，错误优先级尚未定义 | 确认优先级后补入方法规范并建立对应验收；单一错误与有效重放要求可先实现 |
| 浮点与支持范围 | 有限实数公式、绝对误差和异常布尔要求已确定；具体数值表示及极端有限值下的计算保障未确定 | 选实现技术时确认可满足范围及数值方案；若需缩窄输入范围，须先取得接受 |
| E01 整数切分 | “60%/20%/20%、切点向下取整”未写明中间切点是 `floor(0.8*N)` 还是累计各段取整；不足样本门槛未给定 | QA 与项目所有者确认唯一规则、时间相同记录的稳定顺序及不足门槛，再固化边界验收 |
| 无可计入事件的质量汇总 | warmup/错误排除后流无事件或没有任何有效流时，是否纳入宏平均及报告值未定义 | 确认汇总与排除口径；不得自行套用无正例 F1=1 规则掩盖无样本 |
| 比较基线与环境 | 数据集、标注版本、精确 v1 参考实现、H1 配置及质量“不劣于”的比较判据未给定 | 固定这些条件后再对外比较；不得借选型更改方法阈值或读取 test 标签调参 |
| 输出与依赖 | 语言、框架、依赖及评测输出目录/格式尚未选定 | 由后续获授权的实现与 QA 会话确定；逐样本结果留在评测输出，不进入规范 |
